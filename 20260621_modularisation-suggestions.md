# Modularisation Suggestions — Files > 800 Lines

**Date:** 2026-06-21
**Audit scope:** tracked source files (`.rs/.js/.ts/.html/.py/.wgsl`), excluding generated/vendored output
(`pkg*/`, `node_modules/`, `.claude/worktrees/`, wasm-bindgen bundles, `agent-tools/`, `docs/data/`).
**Result:** **~80 files exceed 800 lines.** This doc audits them and proposes a modularisation plan.

**Stated preference honoured throughout:** *libraries get their own sub-folder* (a `foo/` directory with
`mod.rs` + focused sub-modules), not one giant `foo.rs`. There is already precedent in-tree:
`specialized_libs/quantum_biology/` and `specialized_libs/shared/` are sub-folders; the other nine
specialized libraries are still single files. The plan below extends that established pattern.

---

## 0. Guiding principles (so a split helps rather than churns)

1. **Library → sub-folder.** Any self-contained "library/engine/domain" becomes `name/` with a `mod.rs`
   facade and focused sub-modules (`types.rs`, `engine.rs`, etc.).
2. **Preserve the public API.** The `mod.rs` re-exports (`pub use`) everything the old single file
   exported, so **no call sites change** and diffs stay reviewable. A split should be a pure move +
   re-export, ideally with zero behavioural change in the same commit.
3. **Respect the invariants (CLAUDE.md §6).** Do **not** let a split break: zero-heap hot paths, the
   48-byte `NQuin` ABI, the 42 MB `SlgArena`, or the `#[cfg(target_arch = "wasm32")]` native/wasm gating.
   The `gguf_bridge.rs` and `webizen.rs` splits are the ones where this matters most — treat them as
   careful, test-gated refactors, not bulk moves.
4. **Incremental, one file per commit/PR.** 80 files is a programme, not a task. Land the safe,
   high-value, low-risk ones first (specialized_libs); defer the hot-path monster until last.
5. **Don't split generated or vendored files** — regenerate them with better templates instead (see §5).
6. **800 lines is a smell, not a law.** A cohesive 900-line file with one responsibility can stay; a
   400-line file doing five things should split. Prioritise by *responsibility count*, not line count.

**Mechanics (per library, repeatable):**
```
specialized_libs/cryptographic_library.rs   →   specialized_libs/cryptographic/
    mod.rs        // `pub use` facade re-exporting CryptographicLibrary etc. (API unchanged)
    key_management.rs ...
```
Then in `specialized_libs/mod.rs` change `pub mod cryptographic_library;` →
`#[path = "cryptographic/mod.rs"] pub mod cryptographic_library;` **or** rename the module and add
`pub use cryptographic as cryptographic_library;` to keep external paths stable. Move the `#[cfg(test)]`
block into the sub-folder's `tests.rs`. One library per PR; `cargo test -p qualia-core-db` between each.

## 3. Tier 2 — The hot-path monster: `gguf_bridge.rs` (8310 lines) — careful, test-gated

This is the single largest file and the LLM inference engine. It is **not** a Tier-1 mechanical move:
it carries the zero-copy GPU ABI and the native-vs-wasm `cfg` split. Recommend a `gguf/` (or `inference/`)
sub-folder, split along the seams already visible in the file, done **last** and behind the existing
parity tests (CPU≡GPU, tokenizer round-trip, "Paris"):

```
gguf_bridge.rs  →  inference/        (or gguf/)
    mod.rs            // QTensorEngine facade + `pub use`; keep the public surface identical
    gpu_params.rs     // EmbeddingGpuParams, GemmGpuParams, AttentionGpuParams, ElemGpuParams (#[repr(C)] — keep layouts byte-identical)
    mc8_arena.rs      // Mc8WeightArenaBufs, Mc8*UniformArena, Mc8PrefillLayer* (the resident-weight arena)
    pipeline.rs       // WasmGpuPipeline + pipeline construction
    engine.rs         // QTensorEngine core (try_new/init, device/pipeline setup)
    dispatch.rs       // dispatch_* fns (prefill/transformer/attention/gemm/argmax)
    kv_cache.rs       // KvCacheLayout
    load.rs           // GgufLoadReport, adopt_resident_mmap / adopt_resident_q42
```
**Caveats to honour during this one:** keep every `#[repr(C, align(..))]` struct's field order/layout
untouched (they cross the GPU bind boundary); keep `#[cfg(target_arch="wasm32")]` / `not(...)` arms with
their code (don't accidentally merge the wasm CPU-fallback path with the native sync-readback path); run
the wasm build *and* the native parity tests after each move. Given native inference is currently broken
(see `LLM_Q42_STRATEGIC_PLAN.md` §A.3), **fix that first** — don't refactor an engine whose output you
can't yet validate.

`gguf_sharder.rs` (1610) and `llm_agent.rs` (1959) are adjacent and can fold into the same
`inference/` folder (`sharder.rs`, `agent.rs`) once the engine split is stable.

## 5. Tier 4 — Frontend (`docs/`) and **do-not-hand-edit** files

- **Leave generated/vendored files alone — fix the generator, not the file:**

  modules by feature (`benchmark-live/` → `graph.js`, `spatial.js`, `sparql.js`). Do when next edited.

## 6. Recommended order of execution

1. **Tier 1 (`specialized_libs/` 9 libs + 2 domains)** — pure mechanical library→folder moves, fully
   test-covered (79 specialized-lib tests already exist), zero hot-path risk. Biggest line reduction for
   least danger. One library per PR.
2. **Tier 3 app files** that are *registries/dispatchers* (`qapps.rs`, `main.rs`, `commands/mod.rs`,
   `api.rs`) — mechanical, high readability payoff, no ABI concerns.
3. **Decide keep-vs-prune** on the simulated/scaffold modules (`zk_proofs`, `acoustic_ble_mesh`,
   `ambient_orchestration`, `csd_storage`, `ebpf_firewall`) before splitting them — don't gold-plate code
   you may delete.
4. **Hot-path engines LAST and behind tests:** `webizen.rs`, then `gguf_bridge.rs` (+ `gguf_sharder.rs`,
   `llm_agent.rs`) — and only **after** native inference is fixed and the parity tests are green.

## 7. Conventions to standardise (write once, apply everywhere)

- Folder = library; `mod.rs` = thin facade with `pub use` (API stability) + module declarations only.
- One responsibility per file; co-locate each file's `#[cfg(test)]` in a sibling `tests.rs` or `#[cfg(test)] mod tests` at file end.
- Keep `#[cfg(target_arch="wasm32")]` arms intact and together; never merge native/wasm variants during a move.
- Each split commit: **move + re-export only, no logic change**, and it must compile (`cargo check`) and
  pass tests before any follow-up refactor. That keeps every step bisectable and reviewable.
