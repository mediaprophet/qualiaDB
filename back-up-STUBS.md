# QualiaDB — Stub / Non-Functional Code Register

_Generated by audit sweep 2026-10; re-swept and re-verified 2026-10 (§5).
Tracks code that is advertised but not functional, returns fabricated
results, or is honest-but-incomplete. Companion to
`qualiadb-website-update.md`._

Severity legend:
- **FABRICATES** — returns made-up data where a real result is expected
  (worst: violates the project's own "never fabricate" rule).
- **FAILS-CLOSED** — errors honestly; missing functionality, not wrong answers.
- **DESIGN** — intentional capability gate (profile/feature/host contract);
  listed for completeness, not a defect.
- **SCAFFOLD** — structural placeholder acknowledged in comments; low risk
  but easy to overclaim.

1. **Fix first (fabrications that can produce wrong answers):** F9 (mock-model fallback should hard-fail or loudly flag), F10 (QPU simulate-success returns), F25 (record-only packet filtering — security), F26 (constant `"backend_1"`), F28 (silent write failure + path traversal), F29 (HashMap masquerading as ZNS/CSD), F30 (fabricated 2.0× gain), F16 (generated market feed), F13 (LCG-grade randomness in MD).
2. **Fix second (advertised-but-dead API surface):** E2 (filter `stable_mcp_tools` on wasm32), E19 (zeroed-payload fallback should error), E26 (mock endpoints on the router), E4 (parsed-but-never-verified signatures).
3. **Leave, but verify honesty plumbing:** D1–D6 — confirm the failing surface is not advertised as available.
4. **Established pattern holds:** resolved items were fixed the right way — real implementation (F1–F4, F6, F21–F24) or FABRICATES→FAILS-CLOSED conversion (F5, F17, F27).
