Zero-Heap Compliance

Demonstrating QualiaDB's strict zero-allocation architecture for predictable performance

What is Zero-Heap Compliance?

QualiaDB enforces a strict 512 MB RAM floor with zero dynamic heap allocation in hot paths. This means:

  • No Vec, String, or Box in evaluator loops
  • Fixed-size output buffers supplied by caller
  • Stack-allocated arrays for local state
  • Deterministic memory usage - no GC pauses
  • O(1) memory complexity regardless of dataset size

Why This Matters

Traditional databases can consume gigabytes of RAM and suffer unpredictable GC pauses. QualiaDB's zero-heap design guarantees predictable performance even on constrained devices like phones and embedded systems.

The 48-Byte Super-Quin

Every semantic statement in QualiaDB is exactly 48 bytes:

Total: 48 bytes per Quin (exactly 6 cache lines on most CPUs)

Bit-Packed Semantics

All semantic meaning is encoded via bit-packing. No pointers, no heap references:

Subject

FNV-1a hash of entity IRI (63 bits) + MSB flag

Predicate

Property hash (bits 8-62) + opcode (bits 0-7) + modality MSB

Object

IRI hash, integer, decimal, or did:q42 pointer (type tag in bits 60-62)

Context

Sensitivity class (bits 56-63) + contract/world hash (bits 0-55)

Zero-Heap Code Pattern

Here's how to write zero-heap code in QualiaDB:

❌ Wrong: Heap Allocation

// BAD: Allocates Vec on heap
fn filter_quins_bad(quins: &[NQuin]) -> Vec {
    quins.iter()
        .filter(|q| q.predicate == SOME_HASH)
        .cloned()
        .collect()  // Heap allocation!
}

✅ Correct: Zero-Heap

// GOOD: Caller supplies buffer, no allocation
fn filter_quins_good(quins: &[NQuin], out: &mut [NQuin]) -> usize {
    let mut count = 0;
    for quin in quins {
        if quin.predicate == SOME_HASH && count < out.len() {
            out[count] = *quin;
            count += 1;
        }
    }
    count
}

// Usage:
let mut buffer = [NQuin::default(); 1000];
let found = filter_quins_good(quins, &mut buffer);

Stack-Allocated Arrays

// GOOD: Fixed-size stack array
fn process_batch() {
    let mut local_state = [0u64; 16];  // Stack-allocated
    // ... process using local_state
}

The 42MB SlgArena Sentinel

The Webizen VM uses a 42 MB static ring-buffer for SLG tabling:

This prevents infinite stack overflows when querying complex recursive social networks while staying within the 512 MB floor.

Hard Constraint

Any single execution pass must stay within 42 MB. The SlgArena enforces this structurally - if you try to allocate more, the operation fails fast rather than causing silent corruption.

Verifying Zero-Heap Compliance

QualiaDB includes built-in tools to verify zero-heap compliance:

Memory Profiling

# Build with allocation instrumentation

# Run tests to detect heap allocations
cargo test -p qualia-core-db --features alloc-audit
