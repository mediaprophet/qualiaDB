# Swarm S2 C — storage jobs independent review

Read-only source review of Wave S2 C (QBDL storage jobs outside owner locks). Cargo was not run. Author summary was not treated as proof. Production Rust was not edited.

## Review

`StorageJobs` is occupancy only: a `[JobSlot; 30]` plus `live` and a copied runtime owner id. It never constructs a `ReservationLedger`, lease table, quota, or extra `admit_and_reserve`. Original transfer charges stay on the existing ledger until `TransferRuntime::complete_io` releases the original `ReservationHandle`. Cancel and worker-failure only mark `Cancelling` / `Failed`; they do not `ledger.release`. `StorageJobTicket` is non-`Copy`, generation-fenced, and cannot complete without the matching live `TransferTicket`. Native `wait_blocking` takes none of `StorageStage`, `LocalWholeSourceGrant`, `CurrentAuthorityGuard`, or `RuntimeParents`. `write.rs` / `process_crash.rs` are unmodified versus HEAD, so crash barriers are not weakened. `write_leaf` is still the production write path and is not silently claimed as migrated.

No identity- or ledger-defeating bug remains in the reviewed files.

Checklist against the requested attack (source, not summary):

1. **No second `ReservationLedger` / double refund / early buffer reuse.** `StorageJobs` stores `owner`, `[JobSlot; MAX_STORAGE_JOBS]`, and `live` (`submit.rs:7-11`). `reserved_bytes` is a saturating occupancy sum over non-vacant slots (`submit.rs:30-36`), not a charge. Jobs tests construct a parent `ReservationLedger` only as the existing runtime fixture (`tests.rs:58`, `tests.rs:320`). `cancel` calls `runtime.cancel` then sets `JobState::Cancelling` (`submit.rs:121-130`); `observe_worker_failure` does the same then sets `Failed` (`complete.rs:25-34`). Parent `cancel_slot` stamps `Cancelling` and a cancel epoch; it does not take or release the reservation (`dispatch.rs:89-97`). The only jobs-path refund is `complete.rs:48` → `transfer.rs:154-162` (`reservation.take()` + `ledger.release` + `ticket.spent = true`). A second `StorageJobs::complete_io` hits `job.spent` / `ticket.spent` → `DoubleRelease` (`ticket.rs:65-67`, `owner.rs:112-114`, `tests.rs:145-148`, `tests.rs:206-208`). `take_completed` requires an already-spent parent ticket and explicitly does not refund (`complete.rs:53-66`). After cancel, `live_transfers` stays 1, `parent_used` / `charged_window_bytes` stay, `buffer_held` stays true, same-ticket resubmit is `Cancelled`, and a new admit of the same operation is `Conflict` until complete (`tests.rs:175-198`). Slot reuse after complete uses a new `CompletionKey` (`tests.rs:210-212`).

2. **Original charges live until actual I/O `complete_io`, including after cancel.** Submit records occupancy then drops the stage; it does not admit a new budget (`submit.rs:86-116`). Tests snapshot `parent_used` / `charged_window_bytes` across submit (`tests.rs:105-123`), cancel (`tests.rs:175-180`), and simulated worker panic plus `observe_worker_failure` (`tests.rs:240-249`). Refund happens only in `complete_io`. `with_runtime` then asserts the parent ledger host used is zero after close (`tests.rs:83-84`). Dropping a job ticket does not impl `Drop` refund; occupancy leaks until `complete_io` / `take_completed`, which is conservative.

3. **`StorageJobTicket` is non-`Copy`, generation-fenced, bound to `TransferTicket` / `CompletionKey`.** The struct derives only `Debug` (`ticket.rs:47-55`) even though every field is `Copy`; there is no `Clone`/`Copy` impl in the jobs module. `job_generation` is `Generation::next` on the preserved slot generation (`submit.rs:102`, `ticket.rs:38-42`); `clear` keeps generation so a spent ticket cannot match a reused slot. `matches_transfer` refuses `spent` and unequal `CompletionKey` (`ticket.rs:64-71`). `complete_io` requires `&mut TransferTicket` and `&mut StorageJobTicket` and passes `job.key` into parent complete (`complete.rs:39-50`). `CompletionKey` remains Copy and is documented as unable to reclaim a reservation (`types.rs:59-66`); jobs never complete from a key alone.

4. **Identity: job from owner A cannot complete on owner B.** Each `TransferRuntime` takes a unique owner from `NEXT_OWNER.fetch_update` (`owner/counted.rs:32-34`). `StorageJobs::for_runtime` copies that id (`submit.rs:21-23`). `submit_stage` refuses `self.owner != ticket.completion_key().owner` (`submit.rs:71-73`). `validate_job` repeats the owner check and matches slot generation + key (`submit.rs:149-159`). Parent `validate` also refuses `key.owner != self.owner` (`owner.rs:116-118`). Cross-owner complete is `StaleGeneration` both as `jobs_b.complete_io(b, ticket_b, job_a)` and `jobs_a.complete_io(b, ticket_a, job_a)`; live counts stay 1 until the matching owner completes (`tests.rs:263-313`).

5. **Native `wait_blocking` holds no `StorageStage` / grant / `CurrentAuthorityGuard` / `RuntimeParents`.** Signature is `wait_blocking<R>(self, hook: impl FnOnce() -> R) -> R` (`job.rs:26-30`). `ArmedNativeWrite` contains only `reserved_bytes: u64` (`job.rs:14-16`). `arm_write_from_stage` builds a local `StorageStage` and returns the token after that borrow ends (`job.rs:35-46`). `arm_leaf_write` uses grant/stage only inside `accept_local_scoped`, then returns (`job.rs:75-114`). The function cannot capture those types. `write_drops_stage_before_simulated_blocking_hook` mutates the runtime inside the hook, which would not compile if a live `StorageStage` still borrowed it (`job.rs:221-226`). That proves stage drop, not mutex drop. Parent-mutex proof is the jobs wait-site test (item 8). Callers can still *keep* a grant/`TransferRuntime` in an outer frame; the API enables waiting without those borrows and documents that the caller must drop them (`job.rs:12`, `job.rs:71-73`). It does not pretend `write_leaf` now does so.

6. **`write.rs` / `process_crash.rs` protocol was not weakened.** `git status` / `git diff` against HEAD: `storage/native/write.rs` and `storage/native/tests/process_crash.rs` are unmodified. `WriteStep` names, `write_leaf` / `write_leaf_with_hook`, and `store_verified(..., control, authority, ..., hook)` are intact (`write.rs:16-31,35-72,111-126`; `checkpoint.rs:14-28`). Crash child still calls `write_leaf_with_hook` with `CHILD_TEST`, `QUALIA_QBS_CRASH_TEST_ROOT` / `POINT`, `READY`, and the same `WriteStep` mapping (`process_crash.rs:13-20,56-77`). Integrator routing is present: `runtime/mod.rs` has `mod jobs; pub use jobs::{StorageJobTicket, StorageJobs, MAX_STORAGE_JOBS}`; `storage/native/mod.rs` has `mod job; pub use job::{arm_write_from_stage, ArmedNativeWrite}`. `arm_leaf_write` is an inherent impl in `job.rs`; no `write_leaf` replacement.

7. **`may_publish_verified` is false after cancel/fail so verified bits cannot be set.** Returns `Ok(false)` unless the job is still `Submitted` *and* the transfer is still `InFlight` (`complete.rs:10-21`). Cancel sets `Cancelling`; worker failure sets `Failed`; both tests assert `!may_publish_verified` (`tests.rs:182`, `tests.rs:251`). After cancel, `storage_stage` / `check_storage_stage` refuse `Cancelling` with the cancel reason (`storage_stage.rs:64-67`), so a new stage cannot be opened to `store_verified`. `StorageJobs::complete_io` of a cancelled/failed job returns `FinishOutcome::Cancelled` (`tests.rs:200-202`, `tests.rs:256-258`). The jobs layer does not itself write verified bits; the gate plus stage refusal is what blocks publication on this path.

8. **Tests actually drop parent locks (`try_lock` on ledger/leases/ops/scheduler/authority) rather than only commenting.** `wait_site_does_not_hold_runtime_parents_or_authority_mutex` submits inside `CurrentAuthorityGuard` + `RuntimeParents::try_with_runtime`, then those scopes end, then it `try_lock`s `ledger`, `leases`, `operations`, `scheduler`, and `CurrentAuthorityGuard` before complete (`tests.rs:356-371`). `RuntimeParents` holds `&Mutex<_>`, not long-lived guards; `try_with_runtime` acquires loans, runs the effect, then `drop(loans)` (`state/scope.rs:30-53`, `state/parents.rs:18-29,109-118`). After submit the wait region is actually unlocked. Complete uses parent `complete_io` plus `take_completed` (no second refund) and the ledger is zero at close (`tests.rs:373-383`). Named tests from the summary all exist in `jobs/tests.rs` / `storage/native/job.rs`.

## Residual (documented; not a fail)

`write_leaf` / `write_leaf_with_hook` still take `&mut StorageStage` and `&mut LocalWholeSourceGrant` and hold them across `write_exact_at` / `sync_file` (`write.rs:35-72`; `checkpoint.rs:32-45`). `store_verified` still rechecks `StorageStageControl` at every barrier. Grep of production/native tests shows callers still use `write_leaf` / `write_leaf_with_hook`; `arm_leaf_write` + `wait_blocking` are not wired to payload/proof/checkpoint I/O. `ArmedNativeWrite::wait_blocking` only runs a hook (`job.rs:26-30`). The new names (`arm_*`, `wait_blocking`) and the summary residual do not claim `write_leaf` was migrated.

Follow-up constraint (not an S2 C silent completion): `arm_leaf_write` spends the grant through `accept_local_scoped` at arm time (`job.rs:91-113`; `policy/grant/scoped.rs:61-78`), so the one-shot final grant recheck currently runs *before* any future OS wait. Connecting real I/O must not skip post-barrier `gates` / crash hooks.

## Author summary attacks

- “Did not invent a second reservation ledger”: holds. Occupancy table only.
- “`write.rs` was **not** edited” / crash protocol unchanged: holds (git clean vs HEAD).
- “`StorageJobTicket` is non-Copy, generation-fenced, cannot complete without matching live `TransferTicket`”: holds.
- “`may_publish_verified` is false … verified bits must not be set”: holds as a gate plus `Cancelling` stage refusal, not as a store_verified call inside jobs.
- “Native `wait_blocking` … Mutex / RuntimeParents are not held”: holds at the wait function’s types. The native unit test still uses `&mut TransferRuntime` inside the hook (stage-drop proof). The jobs wait-site test is the one that actually `try_lock`s parent mutexes.
- “Did not edit `runtime/mod.rs` / `storage/native/mod.rs`”: those files are now dirty with the requested integrator `mod jobs` / `mod job` routing. That is the required integrator patch, not a protocol weaken. Child production files under the allowed write set match the summary.
- Residual `write_leaf` hold-across-wait is honestly documented and matches source.
