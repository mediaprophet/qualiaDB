# QBS-05 proof sub-contract v1 (implementation candidate)

16 KiB logical leaves belong to one entry and permission scope. SHA-384 outputs are full 48-byte StrongDigest values. The API performs mathematical integrity verification against its supplied root; it does not grant publisher authority or return an authorized consumer handle. QBS-04/06/07 must bind the supplied tree specification and root. No BLAKE3 or existing QBDL hash bytes change.

TreeSpec contains publication_context_id:48 bytes, entry_id:u32, generation:u64, representation:u8 (0 plaintext, 1 ciphertext), key_epoch:u32, logical_length:u64. Constructor caps logical length at 1 TiB and refuses nonzero key epoch for plaintext. Ciphertext leaf bytes are logical length plus exactly 16 bytes (detached tag appended); empty entries have zero leaves and a context-bound empty root. Generation is explicit even when publication context already binds it. All integer encodings below are unsigned big endian with stated widths; byte domains include their terminal NUL.

Common specification encoding is context[48] || entry[4] || generation[8] || representation[1] || key_epoch[4] || logical_length[8].

Leaf = SHA384(0x00 || ASCII qbdl-stream-pq-1/leaf/v1 || NUL || common || leaf_index[8] || logical_leaf_length[4] || encoded_leaf_length[4] || exact encoded bytes). Nonfinal logical length is 16384; final is the remaining positive length. No zero-length leaf is accepted.

Parent = SHA384(0x01 || ASCII qbdl-stream-pq-1/node/v1 || NUL || left[48] || right[48]). Empty = SHA384(0x02 || ASCII qbdl-stream-pq-1/empty/v1 || NUL || common). Tree recursion splits at the largest power of two strictly below leaf count (RFC9162 shape); never duplicate or pad leaves. Proof sibling order is leaf to root. Maximum 32 siblings; proof decoder requires exact bytes and count and rejects surplus proof data. Directions derive solely from index and exact total leaf count; no attacker direction bits.

Verifier is iterative with a 32-element boolean direction scratch on stack. The incremental builder has 33 fixed frontier slots and accepts sequential leaves only. It reports each completed subtree as (start_leaf:u64, leaf_count:u64, digest48) to a caller-supplied fallible observer for optional outboard storage. Observer error or unwind poisons the builder before any callback, permanently refusing a root. A new builder/context or deliberate complete rebuild is needed after failure; emitted nodes are candidate data. Successful finish caches the root, so repeat finish emits no further writes. Durable sink flush/commit is still a separate publication gate. Final fold combines low-to-high occupied frontier slots to produce the unbalanced root. Builder refuses early finish and excess append; root has no heap allocation. Proof encoding uses one count byte then count*48 bytes; exact supplied slice length is required by decoding and encoding returns written length. No registration/publication claim is made for this private profile.

Required evidence: independent Node SHA384 recursive tree/reference proofs for 0,1,2,3,5,17 and >32 leaves; every context/entry/generation/representation/epoch/length/index/byte/sibling mutation rejects; short/extra proof rejects; fixed allocation counter on success/reject/build with positive control; no root promoted to authority. Independent source review by qbs00_crypto found no mathematical defect and requested sink poisoning; that change is implemented, with re-review/tests pending. The 1 TiB tree limit is not an AEAD per-key usage allowance; QBS-10 applies the separate frame/forgery budget. Representation 0/1 selects plaintext/ciphertext of one variant; distinct variants require distinct context or entry.
