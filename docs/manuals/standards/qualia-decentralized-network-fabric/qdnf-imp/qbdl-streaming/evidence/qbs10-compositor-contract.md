# QBS-10 protected compositor — source-grounded next-stage proposal

2026-11-12. Source inspection only; no new implementation or execution. Phase A production crypto is frozen for root validation. This proposes the next exact file claims and preserves every frozen protected-v1 wire byte in qbs10-protection-contract.md. No new crypto primitive, vault, generic permission callback, remote governance claim or public secret-key API.

## Existing owners and exact reuse

* bundle/stream/index::{admit_header,admit_index,AdmittedIndex::entries} supplies original header/index admission and bounded entries. bundle::BundleReader::parse_with_limits supplies existing full-format validation on the publisher's immutable original. PlainPublisher::prepare demonstrates their composition and computes SourceCommit; protected publication must reuse those owners without fabricating plaintext CandidateIdentity or selecting PlainCandidate for ciphertext.
* crypto/network/object_stream::{Context,Descriptor,Inventory,GeometryPage,RootPage,RecipientRecord,Wrap,Delivery} supplies strict structural codecs only. Existing bundle/stream/proof::{TreeSpec,TreeBuilder,empty_root,verify_leaf} supplies actual ciphertext tree geometry/inclusion. TreeBuilder already poisons before fallible outboard callbacks and caches successful finish.
* CryptographicLibrary/KeyManager::begin_object_publication and ::begin_recipient_unwrap supply actual managed key custody. Mandatory provider policy uses existing AccessPolicy and trusted host SigningAccess. ProviderGrant/ManagedOperationControl do not establish application rights. No private get_key clone.
* policy::AuthenticatedClosure owns the existing recognized closure issuer receipt and exact graph. BoundClosure and LocalWholeSourceGrant are specifically tied to plaintext CandidateIdentity; they cannot directly attest protected descriptors. PinAuthority::verify_source/recheck supplies incarnation-bound receipts, exact recognized purpose/audience and current revocation/rotation. Cached results retain receipts, not permanent pin borrows.
* AuthorityOwner::install_grant_with_ceiling/issue_permit/revoke/retire_revoked supplies actual local grants and monotonically fenced reclamation. Existing LocalWholeSourceGrant explicitly represents trusted local whole-source adoption, not remote Share/Sentinel/consent admission. New protected policy code must preserve that distinction.
* EstablishedSession is created only after received peer Finished verification. EndpointAuthority retains the same concrete Mutex<AuthorityOwner>; after_verified samples trusted time around work. PacketProtection owns directional AEAD, packet counters/replay and Drop key erasure. Existing endpoint Route/transport checks actual Bearer source, scope, MTU, frame type and exact lengths. TransferRuntime/storage_stage owns actual reservations, tickets, cancellation and separately charged proof/storage scratch.

## Stage B1: protected source geometry, metadata and publisher

New bundle/stream/protection/{mod,error,source,coverage,metadata,inventory,publisher,finish,tests}.rs; split any file before 500 lines. Parent routing root-owned. No modifications to plaintext limits or lock/catalog bytes.

Source preparation retains a Rust immutable source slice plus the host's actual immutable snapshot/writer exclusion for external storage, as PlainPublisher already requires. Admit the original header/index and full bundle through their existing parsers, cap original entries4096 and source1TiB, preserve original header/index bytes exactly. Caller-charged scratch stores entry ordinal/ranges and maximal complement gaps. Produce exactly one entry object per original index row, including empty rows, plus one object per maximal positive gap between header and suffix index. No synthetic empty gap or arbitrary splitting. These intervals plus header64 and suffix index exactly partition the original bytes; empty entries do not move the interval frontier. Reject duplicate ordinals, overlap, holes, overflow and >8193 rows before generating keys. Use bounded OS opaque-ID generation (16 collision attempts), globally sort IDs, and retain a private mapping to original offsets/ordinals. Never publish names/offsets/source digests/private references.

Calculate M length with checked 288 +108*objects+64+index_length, exact and <=8MiB. This must equal C metadata length before encryption. Context/geometry commit before any ciphertext; roots, descriptor and wraps do not enter M, preventing cycles. The writer obtains masters only through central ManagedObjectPublication, writes M into private zeroizing caller scratch through a crate-private serializer, and never returns a general M byte object or Debug/Clone key-bearing rows. Source hashes in rows are actual SHA384 of original intervals; empty SHA384 is the existing hash of empty bytes.

For each object, begin the managed sealer and existing ciphertext TreeBuilder using exact Ctx/opaque ID/generation/epoch/logical length. Seal one monotonic leaf, append ciphertext plus detached tag to TreeBuilder, then stage ciphertext/outboard through fallible bounded sinks. On every sink error/unwind, cancel the ENTIRE managed publication even when sealing itself succeeded; do not permit retry with the same master/index. Recheck actual current authority before each externally meaningful sink effect and after any blocking call. Earlier partial writes remain unaccepted candidates and retain normal runtime drain obligations. Empty objects invoke no AEAD and generate no master: calculate existing proof::empty_root immediately. Finish metadata similarly as role0/ID0. A successful tree finish is not durable publication.

Construct protected D only after complete exact geometry/root inventory. Verify both page commitments, global ID order, full page coverage and canonical empty roots with existing proof owner (including wrong context/epoch/generation negative tests). Metadata is nonempty. Only a privately constructed ProtectedCandidate may advance to recognized publication. A later immutable full-source hash mismatch aborts the attempt; partial range verification must never be described as full-source reconstruction evidence.

Key-manager borrow issue: ManagedObjectPublication currently retains &mut KeyManager while wraps still require private masters. The same CryptographicLibrary cannot separately admit paired signing at that point. Propose NEW key_management/managed_object/publication_signing.rs child with a narrow method using self.owner.begin_paired_signing and existing managed cose::sign_pair. It signs only protected publisher purpose and exact descriptor/context/scope admitted by the bundle coordinator; validate request binding digest/audience/purpose against those exact values. This is internal managed reuse, not raw long-term signing or a public arbitrary callback. Root owns child routing. No release/reimport of masters or second KeyManager.

## Stage B2: policy-owned protected binding and recognized recipient

New bundle/stream/policy/protected/{mod,publisher,recipient,binding,grant,current,tests}.rs. Existing policy/mod.rs routing only, root-owned; existing AuthenticatedClosure may gain a narrow protected child constructor route, with no changes to plaintext behavior.

AuthenticatedProtectedDescriptor retains exact D bytes/identity, complete validated inventory and AuthorityReceipt verified over SHA384(D), purpose qbdl-stream-protected-v1/publisher, audience opaque_scope_token32. Its principal is the recognized publisher. It is a publisher assertion of ciphertext roots, not proof of reconstructed source or disclosure rights. Cached receipt does not hold PinAuthority borrowed across staging.

AuthenticatedRecipient retains exact A, AuthId and a receipt verified with purpose qbdl-stream-protected-v1/recipient-authority and audience publisher_principal48. A wire pair or arbitrary self-signature cannot install the issuer role. Validate selected publisher, recipient, service, purpose, instrument, operation, scope, source digest/length, closure/policy/consumer digests, D/Ctx and both KEM public IDs against expected local admission. Issuer signing epoch remains distinct from recipient KEM epoch. No wire role/allow boolean. Recheck publisher, closure issuer and recipient-authority receipts with the same actual PinAuthority at every effect, including after staging and before wrapping/acceptance.

ProtectedSourceBinding is privately constructed from recognized D + privately verified M/source mapping + existing AuthenticatedClosure. On publisher side M/source fields come from the actual immutable source owner; on recipient side metadata ciphertext proof, managed unwrap and AEAD authenticate M before parsing, then compare it to already admitted expected private scope. Check manifest source digest/length and policy/consumer membership/reachability using existing closure owner. M cannot select a new policy after unwrap. Source claims in authenticated M remain publisher assertions until corresponding object hashes/full source are actually recomputed. Any full-bundle durable promotion requires exact reconstruction hash and existing bundle parser success.

Trusted local adoption is explicit and covers header/index/gaps/all entries for the exact recipient/purpose/operation. Require same concrete AuthorityOwner issuance; do not accept an arbitrary owner at later recheck. Use existing install/revoke/retire APIs, one short owner guard per bounded effect, no grant slot leak. Scope is SHA384(ASCII "QBDL-PROTECTED-WHOLE-SOURCE-V1\0" || D[48] || Ctx[48] || closure[48] || source[48] || policy[48] || consumer[48] || u64be(source_length) || u8(1)). Existing AuthorityBinding carries exact principal, recipient, purpose, operation and instrument=closure digest. Recipient A.scope and endpoint Intent.scope must equal this exact value. The domain is distinct from plaintext whole-source scope; generation/epoch/predecessor are committed transitively by D/Ctx. Remote Share/Sentinel/labels/consent integration remains open until actual parent owners supply this admission. Managed provider policy alone cannot make this binding.

Important lock composition: EndpointAuthority may use the same Mutex<AuthorityOwner> as protected disclosure. Nested independently locking callbacks would deadlock. Propose a reusable nonforgeable CurrentAuthorityGuard in NEW net/qdnf/authority/current_guard.rs, holding a private MutexGuard and its exact borrowed Mutex reference. Endpoint and protected grant checks both verify affinity to that exact mutex and issue their own exact permits THROUGH THIS ONE guard. Its constructor obtains the lock; no constructor accepts caller-supplied owner/verified state. No permit or mutable owner escapes. Short guard checks fresh time after crypto and immediately before effect; host clock/callback cannot reenter or await. Alternative parent API is acceptable only if it proves identical actual-owner affinity without relocking. No new global owner registry and no cross-owner MutationHandle claim.

## Stage B3: consumed private carrier and delivery

NEW endpoint/established/protected_channel.rs and focused tests, with minimal child routing in established.rs (child access to private EstablishedSession state, root-owned). NEW bundle/stream/protection/{delivery,assembly,delivery_tests}.rs. Narrow existing session/packet_protection.rs repair: use Zeroizing for open's actual 4096-byte decrypted scratch, preserving AEAD/replay behavior.

EstablishedSession::into_protected_channel(self, ...) consumes the installed capability exactly once under current endpoint authority/pin checks; it moves/takes keys and retained reservation and creates one PacketProtection through existing directional key views. No API recreates PacketProtection from with_current for each message, resets packet numbers, exports traffic keys or reinstalls an already-consumed session. Drop/cancel closes the private channel and erases keys/assembly; session's peer Finished provenance is retained. The channel must also retain original route/negotiated MTU: EstablishedSession currently keeps neither. Proposed minimal install change carries validated Common route/MTU into EstablishedSession; accepting unrelated caller route after installation is not sufficient.

Private Q is constructed only inside the protected policy guard after recipient recognition/current grants; call managed wrap_for there, respecting <=16 attempted wraps, then encode existing Delivery. It never goes through public cache/store APIs. Split into canonical <=1024-byte chunks. Existing RecordHeader88 (transcript, request, total, offset, chunk, final) is AEAD AAD, with packet owner authenticating each chunk. Bind exact accepted endpoint Intent parties/service/purpose/instrument/scope/operation to A, not only its transcript digest; endpoint roles choose which principal is publisher/recipient. Retain actual endpoint intent privately in the consumed channel.

Use existing FrameType::SessionDatagram and NextProtocol::QSession, canonical fixed QFrame base header80 with no extensions/fragment flag. Payload is RecordHeader88 || PacketProtection packet (pn8+ciphertext chunk<=1024+tag16). Maximum wire length is80+88+8+1024+16=1216, below existing endpoint minimum1280; no record fragmentation is necessary or accepted. Preserve Route::check and negotiated MTU checks. Require the complete QFrame header to equal its canonical expected form with exact payload length, preventing unbound routing/header alternatives; RecordHeader88 is AEAD AAD. Refuse truncated/trailing bytes and unexpected frame types/flags/extensions. Do not change canonical1024 chunk geometry. Retry WouldBlock retains exact sealed record/frame and cursor, never reseals or increments an accepted-send cursor twice. Fresh current checks precede EACH send retry. Partial send is terminal; retransmission acceptance/durability is not inferred from send return.

Receive checks actual RecvMeta/route/scope/frame/MTU then AEAD/replay before copying into private charged assembly. Expected transcript/request/total/offset/final and exact endpoint intent must match; duplicate/out-of-order/overlap/trailing records refuse. Failed current checks zero the whole private assembly. Existing runtime reservations must cover exact channel owner, record/frame buffers, maximum8192 assembly, metadata scratch <=8MiB and separately charged proof/crypto storage; budget fields alone do not reserve memory. Don't release the original payload credit before actual drain. Packet output and assembly live only inside private guards, never a public generic callback granting plaintext.

## Stage B4: recipient acceptance and object use

First admit expected recipient/private scope and current owner locally, verify recognized A and D/closure receipts, then begin central managed unwrap. Verify metadata ciphertext proof/root BEFORE AEAD and parse M only after all metadata leaves authenticate. Private metadata validation includes canonical byte length/flags, exact Ctx, original parser/header/index geometry, complete mapping/ordinals/maximal gaps, page identity/length equality, empty master/hash rules, nonzero unique masters and no equality with metadata master. The equality check must stay inside central custody; do not export metadata master to the parser. Add a narrow internal validation/install child in existing managed_object owner, not a parallel key vault.

For random payload reads, a new central received-content lease may be created only from that validated private metadata; public arbitrary master import stays absent. Its operations require a short fresh managed-owner admission, current operation fence and protected policy guard. Do not retain &KeyManager for an indefinitely cached lease, which would prevent key rotation; cached state is zeroizing scoped content material plus receipts/IDs, with actual owner borrowed only during bounded acceptance. Each leaf verifies existing ciphertext inclusion first, derives segment, decrypts in private scratch, then samples trusted time and rechecks publisher/closure/recipient receipts, exact application owner and runtime before bounded consumer use. Full scratch is erased after callback/error/unwind; empty objects reach consumers only via authenticated M/canonical empty root/current checks. No generic trait returning Allow.

## Remaining structural omissions and focused acceptance

Phase A does not currently enforce canonical empty roots, original parser/coverage/maximal gap/ordinal checks, original or per-object plaintext hashes, private M framing/duplicate-master comparison, recognized publisher/recipient proofs, live application disclosure grants, durable sink completion, actual resource reservation charging, source snapshot immutability, carrier confidentiality/session-intent linkage, received-object consumer integration or remote governance. This list is an acceptance gate, not permission to publish structural candidates.

Tests by stage: maximum4096 original rows with4097 gaps; all-empty original rows; overlapping/hole/duplicate/gap-subdivision maps; canonical empty root wrong epoch/context; exactly8MiB/one-byte overflow M; public-cache scans for private values; sink error/unwind after successful seal and poisoned retry; immutable-source mismatch; D/metadata/recipient key or scope substitutions; revoke/rotate between authenticate, stage, wrap and acceptance; foreign pin/owner; shared-mutex endpoint+application check without deadlock; consumed session cannot recreate packet counters; real Bearer private roundtrip with independent managed peers; ciphertext retention across WouldBlock; observed route/intent/packet/AAD tamper/replay; early/late expiry and all private buffer erasure; runtime credit/cancel/drain and hot allocation checks. Preserve earlier paired COSE/endpoint independent vectors. Root runs builds after each approved source freeze; no qualification from this design report.
