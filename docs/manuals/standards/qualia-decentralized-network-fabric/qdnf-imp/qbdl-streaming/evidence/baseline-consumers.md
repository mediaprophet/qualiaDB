Scope: source/export and test-inventory snapshot for QBDL streaming consumers. This is a mechanical inventory; the architecture document explicitly calls the new QBDL interface names proposed targets, not current exports (`architecture.md:1-25`). Revision/dirty fingerprints are recorded in `baseline-revisions.json`; do not infer a clean baseline from this note.

## Existing Etalon model byte consumers

- `etalon-model-io` snapshot API: `snapshot/mod.rs:18-20` re-exports `SnapshotError`, `SnapshotLimits`, `CleanupPending`, `Snapshot`; `snapshot/owner.rs:7,13,22,25,29` exposes `Snapshot`, `copy_from`, `bytes`, `identity`, `close`. Lease API: `lease/mod.rs:19-20` re-exports `ModelLease`, `LeaseIdentity`, `LeaseLimits`, bundle identity types; `lease/backing.rs:55,67,139,142` defines the lease and its open/identity/bytes accessors. Integration consumers include `etalon-inference/src/weights/source.rs` and `weights/rows.rs` (both hold `Arc<ModelLease>`); Qwen PLE/NVMe path also accepts a lease (`src/qwen/ple_nvme.rs`).
- Manifest platform facts: `etalon-model-io/Cargo.toml` has no crate features; `memmap2` and `tempfile` are Windows-target dependencies, while `sha2` is general and `tempfile` is dev-only. This establishes a Windows-specific mmap dependency path; it does not establish complete target coverage.
- Reservation/residency existing consumers: `etalon-inference/src/runtime/budget/reservation.rs:11` defines `RequestReservation`; `src/native_resident/planning/mod.rs:65-67` has provider `ModelLease` and `model_lease()` hooks; `src/qwen/p64_runtime.rs:13,32,38` exposes `Qwen4ExpWeightResidency`, runtime and constructor. `tests/storage_contract.rs` is an integration contract test; `runtime/budget` and `native_resident` also contain unit tests. I did not establish a single unified transfer-reservation API from these similarly named mechanisms.
- Governed inference artifact: `tests/storage_contract.rs` contains `RequestReservation` setup (observed at line 70), but no separately named public `InferenceContract` / governed-artifact export was confirmed in this bounded pass. Treat exact artifact shape and enforcement owner as unresolved, not absent.

## P64 and operator-package surface

- P64 reader: `etalon-model/src/p64/mod.rs:14-17` exports `IntegrityMode`, layout items, `P64View`, errors and tensor/manifold views. `p64/reader.rs:50,71,199-259` defines borrowed `P64View`, `parse(bytes, integrity)`, and view accessors (`tensor`, tokenizer, manifold record and schedule bytes).
- P64 streaming builder: `p64/build/mod.rs:19-32` re-exports planning/source/stream/write APIs; `p64/build/stream.rs:9` exports `stream_into`. Payload abstractions are in `p64/build/source.rs` (`PayloadSource`, `ByteSink`, `PayloadSink`, scratch/workspace types); no claim here that a particular carrier is implemented.
- Operator package: `operator_package/mod.rs:22-38,44,51,101` re-exports package components and defines `OperatorPackage` / `PackageBuilder`; access/build methods are at `:51,86,108,129,148,208,220`. Inference-side adaptation is under `etalon-inference/src/operator_runtime/` (`adapter.rs`, `mod.rs`).
- Existing relevant tests: `etalon-model/tests/p64_contract.rs`, `p64_writer_contract.rs`, `p64_plan_error_contract.rs`; streaming fixture at `tests/support/p64_stream_fixture.rs`; operator package coverage includes `etalon-inference/src/operator_runtime/mod.rs` unit tests. Manifest feature facts: `etalon-model/Cargo.toml` defaults to no features; `inference-model` enables `ggml`, serde and inference-kernel, `gguf-index` implies `inference-model`; `ggml` enables half/bytemuck. Thus P64 contract tests are the no-special-feature baseline, while inference-gated compile/use must be run with `--features inference-model` (or `gguf-index` where required). `etalon-inference/Cargo.toml` also defaults to no features and lists backend-specific features; no browser capability was inferred from default features.
- Commands identified from crate layout/manifests (not run by this inventory): `cargo test -p etalon-model --test p64_contract --test p64_writer_contract --test p64_plan_error_contract`; `cargo test -p etalon-model --features inference-model`; `cargo test -p etalon-inference --test storage_contract`; operator runtime unit coverage via `cargo test -p etalon-inference operator_runtime`.
