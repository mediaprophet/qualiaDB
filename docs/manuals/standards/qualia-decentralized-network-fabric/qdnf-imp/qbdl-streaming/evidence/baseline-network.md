## QBS-02 concrete preflight gaps

1. reader_limits.rs:56–115 is reusable allocation-free definite CBOR field preflight. It rejects bytes[6..8] other than zero at line 68. Thus parse_with_limits currently rejects the writer's supported page-align flag 1, while legacy parse reads that flag and checks 4096 alignment (reader.rs:158–181). Unify support for flags 0/1 and reject unknown bits without changing emitted bytes.
2. Progressive parse_header_range checks magic/version and checked index end, but not flags/reserved bytes or negotiated index/remote extent limits (streaming_loader.rs:69–128). from_header_and_index decodes directly with ciborium into Vec then checks only entry payload bounds (147–177): it does not share bounded full-reader count/duplicate/overlap/alignment/digest-length/trailing-data admission. QBS-02 should factor borrowed header/index validation over remote u64 extent before retained allocation.
3. Full bounded admission checks count, required 32-byte digests, unique keys and disjoint payloads (reader.rs:56–99). Legacy parse is a separate historical interface (105–188); preserve explicit compatibility instead of silently treating it as the bounded network admission contract.
4. verify_arrived_range only checks length plus whichever optional CRC/SHA fields are supplied; when both are None it returns Ok (341–373). This must never manufacture VerifiedLeaf or an authenticated arrival. Preserve a distinction between byte-length validation, legacy checks, QBS outer proof and complete-entry checks.
5. BundleReadLimits.file_bytes is usize and defaults to 128MiB (reader_limits.rs:11–24). Remote 1TiB logical extent must be u64 and distinct from resident metadata/scratch limits. Do not raise local whole-file resident bounds globally to handle remote offsets.

## G01 native bearer/session assessment

**G01 is not met by this baseline.** qualification.md:9 requires two real peers to discover/admit/transfer a useful partial object with HTTP, DNS, IP sockets and libp2p absent. Windows/native and independent Linux peer qualification are separately required at lines 38–39. The reusable path can support the implementation, but a local verifier, an in-process queue, a successful AF_PACKET open, and a loopback WSS demo are different evidence classes.

- NativePeer currently stores concrete IpcEndpoint (host/mod.rs:36–49), and its authorised helper creates both in-process IPC peers under one HostAdmission. exchange.rs:14–21 fixes a 4096-byte protected payload cap. This is meaningful protected IPC evidence but not an independent provider/client, large leaf transfer, or cross-process/platform native bearer.
- handshake_over_fragments<I,R> accepts two Bearers but orchestrates both sides in one call (session/handshake/fragmented.rs:180–310). It creates both X25519 inputs, both signing key pairs and the ML-KEM secret locally (199–208); computes and compares both shared secrets (277–279); derives both keys and confirms both Finished values in that process. Reuse the primitives and fragmentation codec, but independent peer state machines, peer-authority pin/chain binding, and separately received Finished confirmation must be owned by QBS-04/parent NET/CRY integration. This helper alone is not two independently authenticated peer sessions.
- Linux raw_ethernet/linux.rs:31–82 opens nonblocking AF_PACKET with development EtherType 0x4242 and binds the interface; send/recv implement Bearer (98 onward). raw_ethernet/mod.rs:1–12 and unsupported.rs explicitly return PlatformUnsupported on Windows/non-Linux. physical_two_host_qualified and veth_namespace_qualified are false (mod.rs:58–68). two_host.rs:1–5,24–41 is a truthful capability probe, never a delivered two-host transfer.
- qdnf/harness/two_process.rs:61–100 exchanges eight fixed bytes over a Unix stream in a child process and expressly limits evidence to Process; non-Unix returns PlatformUnsupported. It does not run QLink/QResolve/QSession/QBDL and cannot stand in for G01.
- Minimal bridge: retain Bearer ownership behind an independently driven native session endpoint, bind service/purpose/operation/policy and confirmed pinned authority, provide a real non-IP Windows process bearer plus an independent Linux peer implementation, then connect the QBS record codec/provider/client/storage and demonstrate useful partial consumption. If a cross-host bearer is claimed, qualify it separately on actual supported hosts and retain physical-link flags truthfully. No existing flags should be flipped merely to satisfy a gate.

## HTTP, WSS, WebRTC and reliable-carrier baseline

- Real native local TLS WSS exists: p2p/connectivity/wss_tls.rs::{mint_ca,mint_server,server_config,client_config,loopback_tls_wss}; cscp_wss.rs::cscp_then_qsession_over_local_tls_wss (44); WssBearer<S:Read+Write> implements Bearer (wss_bearer.rs:42–82). - WSS framing has a 2048-byte frame / 2036-byte payload envelope (wss.rs:16–18), allocation in masking/send and receive Vec (119,146), and a 1280-byte Bearer MTU (wss_bearer.rs:47–48). It is reusable compatibility groundwork, not zero-heap QBS 16KiB records, browser credit/backpressure/Origin/compression conformance or a PQ authority claim from TLS.
- PathTable::duplicate_recovery_on_compat_carrier returns false with the NET-05.11 contract comment (session/paths.rs:239–242). This is a declarative contract, not by itself evidence of negotiated execution mode. cscp_h2.rs:1–4 still explicitly describes nested reliable-stream recovery/head-of-line degradation. - BrowserProfile::{RELAY_ONLY}, BrowserBearer::{WebrtcDataChannel,WssFallback} and IceTransportPolicy are real policy contracts (net/peer/connectivity/browser.rs). p2p/connectivity/IceAgent plus STUN/TURN codecs/candidate admission exist; they are not an implemented browser data-channel binding. connectivity/evidence.rs:33–80 expressly leaves public relay, Internet two-host, independent review, browser TURN/WebRTC interop and native independence from that path false. - Cargo.toml:124–128 provides qdnf without pulling libp2p and optional libp2p-compat. Existing reqwest/rustls/Tokio dependencies are present (300,334,361–370); no dependency upgrade is required merely to freeze core QBS interfaces. Feature/compile behavior is not tested by this inventory.
