# QBS-12 source map: partial admission for existing formats

Status: implementation-ready map, not an API/security claim. Read alongside QBS-02/05/06 and `task-registry.json` QBS-12. It records the current full-file codec boundaries and the narrow adapter gap needed to consume authenticated, complete subranges. A QBDL proof authenticates only the requested entry leaves; it must never be reported as whole-container verification.

## Source owners and current behavior

- **Q42 integrity:** `src/q42/chunk_integrity/mod.rs` defines `BLAKE3_TRAILER_BYTES = 64` and full trailer verification. EMF imports this helper (`src/q42/emf_container/reader.rs:6`); M64 imports it (`src/q42/m64_matter/checked_reader.rs:6`). Directory indexes are `src/q42/DIRECTORY_INDEX.md` and `src/container_10d/DIRECTORY_INDEX.md` (the nested EMF/M64 directories do not have their own index files).
- **EMF scientific bricks:** `src/q42/emf_container/reader.rs:17-25` defines explicit `EmfReadLimits`; `EmfContainerReader::parse_with_limits` begins at `:61`, parses header/directory and verifies every current-format full BLAKE3 payload trailer at `:157-188`. `chunk_entry`, `chunk_payload`, and `cell` are at `:232-260`; `chunk_payload` returns only `cell_count * 64` record bytes, excluding a trailer. `lookup_brick_cell_at_time` and bounded directory work are at `:284-292`; `dense_volume` is at `:297` and allocates a full dense result, capped by `MAX_DENSE_CELLS`. Writer/reader integration tests in `src/q42/emf_container/mod.rs` include payload tamper detection (`FullHashMismatch`), explicit file/chunk limits, and lookup. New v2/v3 format tests are in that module; preserve concurrent EMF extension work and keep the adapter outside it.
- **M64 geometry/scientific chunks:** `src/q42/m64_matter/checked_reader.rs:15-25` exposes explicit `M64ReadLimits`; `M64Reader::parse` at `:124` and `parse_policy` at `:142+` validate all directory rows, checked bounds/alignment/overlap using caller `&mut [M64PayloadInterval]`, all full-BLAKE3 trailers, record shape/CRC, and record count limits before constructing the immutable view. Full 256-bit digest verification is at `:294-300`. `chunk` at `:400` returns borrowed record bytes, and `M64Chunk::payload` / `record_bytes` are at `:416-435`; the payload excludes the full-hash trailer. Full reader tests in this module cover full digest and legacy-prefix opt-in. Legacy short hashes stay migration-only and cannot be labeled full verification.
- **10D geometry sections:** `src/container_10d/header.rs:206` parses the 64-byte header; `src/container_10d/section.rs:54` gives the actual `SECTION_DESCRIPTOR_SIZE = 24`; `SectionDescriptor` at `:265` is `repr(C)` with section type/tier/reserved16, byte offset/length, stride/count and CRC32C. `parse_section_table` at `:667` returns a zero-copy `&[SectionDescriptor]` but requires the complete `data` slice; it validates descriptor reserved/type/version/tier, offset/alignment/bounds, CRC32C, overlap and zero padding. `SectionType` maps mesh=1, nodes=2, topology=10, spatial index=11, manifold identity v2=15, etc. at `:66-150`. Mesh decode is in `mesh_section.rs`; topology and BVH/kd-tree are `topology_section.rs` and `spatial_index_section.rs`. The table parser's existing CRC32C is a format check, not QBDL authentication or a full-container integrity label.
- **Whole-file distinction:** `.10d` `integrity.rs` whole-file CRC API (`verify_whole_file_crc32c`) requires mutable full bytes; selective section admission cannot claim it. QBDL's outer SHA-384 leaf/root proof remains independent of inner CRC32C/BLAKE3 checks.

## Minimal adapter boundary

Add format children under the planned `bundle/stream/formats/`; parent routing remains root-owned. Do not copy the codec or expose unauthenticated raw bytes as ready-to-use data. Inputs should be borrowed exact header/directory/descriptor bytes plus the authenticated selected payload span, declared whole-entry length and explicit caller budgets. Outputs should borrow from the caller's authenticated byte buffer and carry a precise verification enum/state (e.g. selected inner chunk verified; directory/section closure structurally validated; outer proof verified elsewhere). No allocation or dense volume conversion on the QBDL path.

1. **EMF/M64 selected chunk:** bounded parse of header and the complete fixed-width directory (respecting existing max-file/max-chunk/max-record limits); validate all directory geometries and global metadata non-aliasing with checked arithmetic. For requested index only, require complete record bytes **and all 64 trailer bytes**, verify full BLAKE3 over record bytes using `verify_blake3_trailer`, and return a borrowed record span without trailer. Must not call current full-file `parse` on a stitched sparse buffer. For M64, caller supplies interval scratch sized to directory rows; for EMF, existing pairwise overlap scan is O(n²), so enforce a small explicit chunk cap and/or add caller-owned interval scratch before scaling. Existing EMF default max 4096 has quadratic overlap admission cost; do not silently lift it for hostile partial metadata.
2. **10D section closure:** parse the authenticated 64-byte header and actual 24-byte descriptor rows from the source table, with a separate small section-count/metadata-byte budget. Validate descriptors against declared source length using checked offsets, type/tier/reserved/version/stride rules and duplicate/overlap constraints. Fetch only selected section bytes, verify its descriptor CRC32C as inner consistency, and feed borrowed bytes to the existing typed decoder. Select the minimal transitive dependency closure, not every section: quantized mesh section for bare geometry; add topology/spatial-index/material/texture/field sections only when the selected operation requires them. For indices and cross-section references, validate required dependent sections before decoding; absent optional dependency is not evidence the complete original file is valid. Avoid borrowing `SectionDescriptor` by casting an incomplete remote slice until alignment/lifetime requirements are met; an aligned caller buffer or explicit fixed-byte decoder is needed.
3. **Admission accounting:** bound header bytes, directory/descriptor count and bytes, fetched authenticated ranges, scratch, and output. Use fallible checked integer conversions and caller-owned output/scratch; return required length before writing. A malformed/torn last trailer must fail even when the QBDL proof covers the data portion. Exact outer descriptor/source linkage remains QBS-06/07 responsibility.

## Tests and dependencies

- Fixture tests should create one small valid EMF brick and one full-hash M64 chunk with independent expected complete 64-byte trailers; mutate the final trailer byte and assert rejection. Exercise directory-bound, alias/overlap, misalignment, truncation at every trailer boundary, unsupported legacy prefixes, per-format count/file/output limits, and checked-overflow vectors. Positive result must expose borrowed payload pointer/slice and assert no owned payload allocation.
- Create one small `.10d` with an actual 24-byte descriptor table and mesh payload; authenticate/fetch only the header, table, selected mesh section, and required closure. Verify exact bytes go through existing mesh decoder; mutate descriptor CRC/reserved/tier/offset and include missing required topology/spatial dependencies for an operation that requests those features. Confirm section CRC alone is not described as whole-container authentication.
- Reuse `chunk_integrity::verify_blake3_trailer`, `EmfChunkDirectoryEntry::validate`, `M64ChunkDirectoryEntry::validate`, `Container10dHeader::parse`, `SectionType`/`AlignmentTier`, and existing typed section decoders. Avoid new hash implementations. Add actual-source fixture tests under the new adapter's tests, not by expanding unrelated EMF extension or legacy migration code.
- Platform/verification unknowns: existing 10D borrowed descriptor view has an alignment constraint; exact supported partial input shape is not presently exported in this inspected surface. QBDL implementation must decide its private adapter contract and test Windows plus independent Linux/browser target behavior later. This map ran no builds or tests and makes no target-support claim.
