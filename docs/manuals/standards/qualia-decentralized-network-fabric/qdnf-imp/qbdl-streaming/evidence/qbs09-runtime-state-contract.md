## One actual state and one existing transition implementation

Existing TransferRuntime exclusively borrows actual ledger/lease/operation/scheduler parents for its lifetime and holds private persistent slot/generation/charge state. A runtime cannot simply be dropped/recreated on WouldBlock. The selected design MOVES its exact nonborrowed fields into private RuntimeData BETWEEN polls. No Clone, copied table, new caps, reservation recreation or release/re-admit. Non-Copy RetainedRuntime holds Option<RuntimeData> plus exact parent registration. Some(data) owns the state outside a poll; None is a privately borrowed shell while the temporary existing TransferRuntime owns those SAME handles/slots.

A short scope acquires actual parent locks and completes all affinity/incarnation/charge/lease/operation/scheduler preflight BEFORE taking data. RuntimeData::attach is an infallible struct move into the EXISTING TransferRuntime, preserving owner/serial/slot generations/cancel/queued records/static+control/workspace/source handles. Existing admit/poll/issue_credit/cancel/complete_io/storage-stage methods run unchanged through a narrow RuntimeAccess forwarding view. It has no DerefMut/raw mutable runtime/parent escape, so a callback cannot replace the engine wrapper through that view. Public legacy TransferRuntime signatures and stage implementation remain intact.

Restore guard owns the temporary runtime and exclusive empty destination. On return/error/unwind its Drop infallibly moves every actual field back. No callback, allocation, validation, lock or assertion is in restore Drop. Private attach/extract field destructuring is compiler-checked against future struct-field additions; TransferRuntime must remain without custom Drop. Take/restore never admits/releases budget or resets counters. A callback's actual completed transitions remain completed even on error/panic; no rollback fiction.

catch_unwind sits INSIDE the parent guard lifetime. Restore runs while unwinding the callback, catch receives the original payload, actual parent guards drop normally, THEN resume_unwind continues. Thus a caught callback panic does not poison these parent mutexes; original state/tickets may be reopened. This does not repair already-poisoned foreign parents or a separate application authority mutex held by user code. Scope errors preserve data and charges. Actual I/O drain is still required before completion/reuse.

No public from_caps/from_fields/decode. Returned owned tickets/credits/pages retain original owner IDs; scoped runtime/stage/control/parent borrows cannot escape. Source-generation/policy/rights are not granted by this access view.

Legacy close is factored once into owner/close.rs with a recorded phase: Open -> ControlReleased -> ControlChargeReleased -> Closed. Each successful actual step records progress; checked ledger release failure restores only the exact private consumed handle. Retry does not replay already-consumed control operation. used_bytes decrements only after successful corresponding release. require_open refuses partially closing runtimes. Consuming retained close refuses while live/queued/workspace/source ownership remains and returns original state for retry; registration clears only after actual final close. Drop does not fake cleanup/refund. No new durable/serving authority.

Actual read/write/sync must NOT be executed inside short poll and described as cooperative.
