Status: source-inspected design for review; no implementation, build, remote qualification or permission claim. Source HEAD afbe431195167fde0fadc233ed79fd2fe85f73f0, working tree includes concurrent uncommitted implementation. Paths below are relative to crates/qualia-core-db/src unless prefixed otherwise. This supplements qbs07-policy-contract.md and qbs10-compositor-contract.md; existing protected-v1 bytes remain unchanged.

## Finding and recommended first profile

The library has real signature, key custody, consent, labels, semantic evaluation, Sentinel/graph policy, native delegation and current session/grant owners. The missing part is their **authenticated whole-source disclosure composition**. Neither a structural closure, a VerifiedLabel, a PinAuthority receipt, a successful semantic assessment, a managed provider policy nor an established session supplies that composition individually.

Implement a bounded direct-controller profile first: an explicitly enrolled controller may issue remote whole-source grants for an exact enrolled source and policy; the actual controller owner evaluates current consent/policy and signs the existing RecipientRecord. The receiver/publisher verifies this paired proof and a fresh session-bound decision, then installs a derived current grant into the existing concrete QDNF AuthorityOwner. Local bootstrap establishes who may govern the source; it must not silently authorize each transfer. This differs materially from LocalWholeSourceGrant: per-transfer authorization comes from the remote controller's paired signature and actual current policy execution, not a local caller constructing LocalGrantRequest.

Reject unsupported delegation chains, unknown source controllers, unknown/mixed coverage, missing required co-consent, and unknown policy versions. Do not label this first direct-controller profile as universal human consent, clinical consent, or a completed distributed revocation protocol.

## Minimal new authenticated schema and upstream trust

1. **Recognized controller enrollment, local administrative boundary.** A small fixed table associates an existing PinHandle/principal with exact source SHA384+length, exact policy artifact digest, allowed publisher principal, allowed operation set, expiry and maximum decision lifetime. Installation requires an unexported local-admin capability analogous to existing LocalBootstrap. No wire role flag can install this association. Initial capacity eight, no implicit eviction. Default deny; no source wildcard and no transitive delegation. This table stores authorization metadata only, not keys, signatures or a second vault. PinAuthority remains the paired-key owner. Rotation must explicitly replace recognition and invalidate old decisions, never preserve a stale PinHandle.

   This enrollment says which controller the host recognizes as authoritative for that exact source/policy. It does not prove universal ownership/personhood. If the source needs several principals' consent, direct single-controller enrollment is insufficient unless a separately authenticated upstream mandate covers them; otherwise refuse. Do not create an 'all subjects consented' input boolean. Existing medical/native grants may be checked by future domain adapters using their real owners, but cannot be silently upgraded to paired authority.

2. **Whole-source disclosure policy artifact.** Add a versioned bounded artifact in the existing signed closure, whose original bytes bind: exact source SHA384+length; whole coverage (header, original index, gaps, every entry); recognized source-controller principal; publisher; original source label digest; original dependent label digests; allowed recipient/purpose/operation/consumer references; and mandatory executable rule/graph references. Policy and consumer rows must be reachable from the manifest root. Existing manifest must remain acyclic: no descriptor/context IDs in it. Per-transfer A below supplies those later commitments. Count this artifact and all original dependencies inside the existing combined 1 MiB closure budget, <=16 nodes, <=256 explicit edges. No new parallel semantic graph or renamed lock/catalog bytes.

   First profile has one issuer-attested whole-source label plus <=16 closure labels. Validate every original label encoding/digest and bind issuer identity to the recognized paired assertion before feeding VerifiedLabel into JobLabelContext. A publisher's local scan must independently confirm complete original source coverage. Receiver verifies complete private M mapping before payload use. Reject partial labels, mixed undisclosed ownership, missing gap coverage or unsupported per-entry exceptions. The whole-source statement is an authenticated controller assertion, not proof that the signer actually owns human data.

3. **Reuse RecipientRecord A as the exact remote authorization payload.** Its existing 1856-byte schema already commits D, Ctx, recipient, publisher, service, purpose, instrument, scope, operation, closure, policy, consumer, source+length, recipient KEM epoch/validity and BOTH ML-KEM-768/X25519 public keys. Use unchanged RECIPIENT_PURPOSE = qbdl-stream-protected-v1/recipient-authority and the existing paired COSE Binding. The signer is the recognized source-authority issuer for this scope; arbitrary self-signed recipient keys are insufficient. A's recipient need not equal its issuer. A proves authorization of those recipient keys; successful managed unwrap establishes the receiver actually controls them. Keep issuer signing epoch distinct from recipient KEM epoch.

   Check every A field against independently selected admission/session/source state, not against values copied from A itself. Use the existing protected whole-source scope domain in qbs10-compositor-contract.md, and require endpoint Intent to match parties/service/purpose/instrument/scope/operation. Verify independent publisher D and closure receipts as well as A. D roots cannot be justified by the closure's source hash alone.

4. **Fresh remote decision ticket, separately versioned control artifact.** A has no transcript, challenge or controller-status generation. Do not smuggle these into its frozen fields. Proposed ticket binds A.id(), exact accepted endpoint transcript, request ID, fresh verifier challenge[32], recognized controller generation, exact policy digest, action (metadata release or payload use), not-before/expiry and a monotonically consumed decision ID. Canonical fixed-width codec and exact label/domain need a small subsequent freeze before code; proposed paired purpose qbdl-stream-protected-v1/disclosure-decision. It is a separate bounded private control message, not an extension to unchanged Delivery/RecordHeader and not silently appended trailing bytes. Bound ticket+paired envelope to 8192 bytes; use existing canonical 1024-byte record chunking under a distinct negotiated control-message discriminator.

   The verifier owns a bounded outstanding-challenge slot tied to current channel transcript, request and local owner incarnation. Consume once only after actual paired verification and policy agreement; duplicate/cross-session/restart replay refuses. No resumption from serialized tickets; restart requires fresh challenge. Controller issues only from its concrete current policy/consent owner, using central managed signing and a fresh clock under its short current guard after expensive work. The ticket expiry is <= every underlying grant/pin/policy expiry and locally configured lease ceiling (propose <=30 seconds, configurable only downward for this profile).

   A delayed remote revocation cannot become instant knowledge at another machine. This profile provides current local-owner checks and bounded remote leases: deny immediately when authenticated revocation/disconnect is observed, otherwise no later than lease expiry. If a policy requires stricter freshness, require a fresh decision for each bounded effect or refuse that policy. Do not claim revocation-complete offline operation or persistent antirollback from an in-memory nonce table. A durable/offline profile remains a separate gate.

## Actual policy execution and current-use composition

The adapter must produce a private nonconstructible DisclosureDecision, never accept PolicyOutcome::Allow or a generic trait returning bool. Before evaluating graph rules, require the positive recognized remote grant and exact full-digest scope checks. Use actual existing ConstraintInstruction::lower + WebizenVM::execute_constraint and evaluate_inference_guard for the policy artifact's bounded authenticated program/graphs. Match the parent bounds: <=64 instructions, norms/epistemic <=256, facts and trace leave room for the one locally constructed observation; explicit finite/register/operation checks. Required claims and temporal checks may not disappear because a malformed artifact supplies zero; schema must explicitly name the required profile and reject missing mandatory inputs. Every result other than complete Allow refuses byte effects, preserving Steer as unresolved.

Reduced graph identifiers are lookup/evaluation tokens only. Build them from an authenticated symbol mapping, reject collisions among admitted full identifiers, and never let a u64 alias replace the exact A/source/controller comparisons. Reject unsupported time conversion above u32::MAX while using the current guard engine; do not truncate clock values. Facts about recipient environment, actor session or performed operation must come from concrete local owners, not a peer-supplied list.

Join existing labels, seal before egress, then call admit_egress/admit_caller_egress with authenticated actual recipient/purpose/compartment and locally established environment profile. Add a small explicit operation-to-restriction mapping: NO_REDISTRIBUTE forbids this Share action; NO_EXTERNAL_AI, NO_TRAINING, NO_BIOMETRIC_REUSE and NO_PUBLIC_INDEX require known corresponding consumer action/environment and refuse prohibited uses. Unknown restriction bits or unclassified consumer actions fail closed. No declassification/release_derivation in first profile. The mapping is policy glue, not a replacement label lattice.

After successful remote verification/evaluation, derive the exact AuthorityBinding and install through existing AuthorityOwner::install_grant_with_ceiling. Retain its same Mutex reference and private MutationHandle, plus private pin receipts, decision/challenge provenance and authenticated artifact references. CurrentAuthorityGuard checks session handle and application handle against this same owner inside one short guard. Recheck receipts, time, current policy/controller generation, action and resources immediately before every wrap/send retry/plaintext consumer effect and after expensive crypto. Do not cache PinAuthority by immutable borrow across staging; borrow only during a short use so hosts can revoke/rotate between operations.

Cleanup must explicitly revoke+retire the application's eight-slot record through a narrow guard child; no slot reset or generation reuse. A pending async operation cannot outlive cleanup. If Drop cannot obtain the nonblocking owner lock, record bounded pending cleanup in an existing owner-managed lifecycle path or keep capacity occupied until explicit close; do not silently leak forever or mutate without the lock. This lifecycle choice needs an explicit implementation test, not a destructor that assumes uncontended locking.

## B2 wrap/receiver and QBS09 integration surfaces

- Publisher: add a focused protection child that receives only the private authenticated remote-grant owner. Under its short current guard call the existing ManagedObjectPublication::wrap_for(A, out); then unchanged encode_delivery. Provider policy and <=16 wrap attempts remain independently enforced. Use the existing managed with_current_effect/sign_descriptor machinery; never relock ManagedOperationControl from within its own guard. Failed/stale/unwound effect destroys unpublished private output and cancels the attempt. No public master export or recipient key generator.
- Channel: use actual consumed EstablishedSession -> ProtectedChannel -> ChannelIo::with_current -> FrameIo. This already retains one PacketProtection/packet sequence, real Bearer, route/MTU, peer receipt, intent and reservation. Pass its existing CurrentAuthorityGuard into application rechecks; do not acquire another guard for the same mutex. send_pending retries must recheck the application grant too, even for a previously sealed pending frame. A transport permit alone is insufficient. The separate decision control record must not bypass private assembly or the <=8192 package bound. Existing ChannelIo::with_runtime_scope/resource bridge should own actual reservations, not budget numbers invented by the adapter.
- Receiver metadata: KeyManager::begin_recipient_unwrap(RecipientUnwrapRequest, control, clock) verifies actual manager-held Kyber/X25519 keys and Decrypt/Derive policies; crate-private unwrap consumes this capability. UnwrappedMetadata::decrypt_next is monotonic/fenced, but does not verify ciphertext tree inclusion or app permission. Verify recognized D and metadata tree first, then AEAD each private leaf, then parse complete M within <=8 MiB before any consumer access. Keep private metadata entirely out of public descriptor/cache APIs.
- M parser: new private decoder for the existing writer schema, not another QBDL parser. Reuse actual admit_header/admit_index and the B1 source coverage logic against retained original header/index. Validate exact length 288 +108*N+64+index_length, sorted opaque IDs distinct from original ordinal, canonical complete entry/maximal-gap partition, exact geometry, source and closure/policy/consumer refs. Existing proof owner checks every canonical empty root. Reject empty metadata, wrong empty-object master flag/hash, duplicate masters and master equality to the metadata master inside central custody. A valid publisher assertion does not replace recomputed object/full-source hashes.
- Payload: add a narrow managed_object received-content child admitted only from privately validated M and the remote-grant guard. No public arbitrary master import/export. Verify ciphertext inclusion before decrypting; use existing ObjectScope/segment KDF/AEAD and provider fencing; fresh app checks before bounded consumer access, zero scratch on return/error/unwind. Full-source promotion requires actual source hash/reconstructed parser success; partial verified objects cannot claim that full check happened.

## Proposed narrow ownership and staged tests

Stage R1 (schema/reuse, no crypto primitives): NEW bundle/stream/policy/remote/{mod,recognition,policy,codec,decision,tests}.rs. Purpose-scoped recognition contains no keys. Small existing parent mod routing only. Prefer mechanically extracting reusable policy schema/helpers from governed/program.rs into a neutral governance child if feature routing otherwise forces an inference dependency; do not copy its instruction semantics. No mandatory Poet adapter.

Stage R2 (actual issuance/current ownership): NEW bundle/stream/policy/remote/{issuer,grant,current,lifecycle_tests}.rs plus a narrowly claimed net/qdnf/authority/current_guard child for install/retire operations with exact owner affinity. Existing PinAuthority and central managed signing unchanged except a focused managed decision-signing child if needed. This stage must include two independently owned controller/verifier states; a local helper that manufactures both trusted facts is insufficient.

Stage R3 (B2 and receiver): NEW bundle/stream/protection/{authorization,wrap,metadata_decode,receiver,receiver_tests}.rs and NEW key_management/managed_object/{received_content,received_tests}.rs. Minimal existing publisher child method routes to its retained publication owner. No replacement vault. Root owns the QBS09 channel carrier routing/extension and build coordination.

Required independent tests: positive recognized remote whole-source issue/verify/use; arbitrary paired self-signer denied; right key wrong role/source/policy denied; A substitution of either KEM key, D/Ctx/source/length/operation/recipient/epoch denied; unreachable policy/consumer, missing gap/header/index coverage and mixed owners denied; authentic label bytes with unauthenticated issuer denied; every restriction and missing actual environment denied; VM deny/Steer/unknown opcode/graph overflow/missing positive grant denied; nonce replay/cross-session/expired ticket/restart/rollback denied; revoke/rotate after authenticate/stage and before wrap/send/consumer denied; shared actual-owner guard no deadlock; eight-slot exhaustion and revoke/retire reuse; WouldBlock keeps exact ciphertext but refreshes app checks; metadata proof/AEAD tamper, truncated/trailing M, ordinal/ID swap, duplicate/empty master and canonical empty-root failures; source mismatch and incomplete reconstruction cannot promote; cancellation/unwind erases all private buffers. Existing independent COSE/KDF vectors and full physical endpoint tests remain prerequisites, not substitutes for this composition.

Acceptance remains open until real remote issuer, receiver, policy and carrier integration tests execute. This report does not promote local adoption, parent health consent, native authoring authority, structural Phase A, or a pin receipt into a completed remote Share qualification.
