## 2. First implemented profile and explicit authority boundary

Initial proposed service is plain whole-source-authorized candidate delivery, one selected entry and one leaf per transfer request. It can avoid downloading unrelated payloads, but its original index/names/header/commitments expose whole-source metadata. The local trusted host must authorize ALL original bytes and metadata, exact peer/purpose/operation, before sending even Describe content. No automatic public treatment from PlainCandidate, publisher signature, peer key confirmation, filename, group membership, payment or a successful proof. Mixed/private originals, private projections and protected object recipient wraps return Unsupported in this profile; QBS10 keeps its separate owner and representation.

Bootstrap assumes the local host has selected the exact expected publication/source/closure and granted whole-source scope out of band. No unauthenticated object enumeration, object-existence oracle or remote request that chooses a new local policy. The same BoundClosure/current pins and actual whole-source binding must match endpoint Intent service, parties, purpose, instrument, scope and operation before disclosure. Do not assume two matching transcript digests imply matching application intent.

LocalWholeSourceGrant is one-shot, non-Copy, owns a private handle and borrows the actual AuthorityOwner; accept_local_scoped marks spent BEFORE effect, supports repeated recheck and checks after callback. It must remain one-shot. The common current_guard bridge needs a narrow sibling grant implementation under policy/grant/current.rs retaining exact owner affinity and private local handle while borrowing the one current guard only during a bounded effect. Existing public local grant behavior stays intact. Canonical AuthorityOwner has8 records: endpoint plus content handles and any simultaneous grants must fit that actual table; timely explicit close/retire is part of admission, not a larger copied table. Each bounded disclosure uses an actual owner-issued scoped grant (including close/retire on every exit); no replayed borrowed grant, reinstall under a fresh unrelated owner, raw permit escape or generic Fn()->Allow adapter. Native storage acceptance continues to own the outer scoped call and commits the page attempt only after outer and runtime final checks. Any grant-owner adaptation needed to feed that path is a separately reviewed canonical policy child, not a service-owned duplicate AuthorityOwner.

Remote governance is a remaining package, not an absence claim about policy engines. Inspected concrete owners exist: WebizenSentinelGate in poet_host/vibe_sentinel/policy_gate.rs evaluates real deontic NQuins with admit_call, validate_post_execution and bounded receipt sink; net/qdnf/contracts/evaluate.rs checks exact pinned contracts, referents, provenance, generations and temporal delegation; governance/consent_contract.rs ConsentLedger::authorize_category_access retains revocation against omission for health-category grants; net/qdnf/session/contact.rs admit_contact checks current purpose/contact/grant; economics/consent.rs explicitly forbids payment enlarging consent or host budgets. The current health consent format is Ed25519/SHA256 with32-byte identities, not this programme's paired48-byte descriptor/recipient authority. These real APIs are not interchangeable wire authorizations and their reports/tickets do not directly mint a whole-QBDL grant.

Concrete remote integration owner proposed under bundle/stream/policy/share/{mod,request,admission,current,tests}.rs, with actual Sentinel/contract/contact/consent owners borrowed by the existing governance host. It must bind exact full source/header/index/gap/entry coverage, descriptor/context, closure/policy/consumer, recipient/service/purpose/operation, issuer/delegation and current revocation generations; validate labels/rights before any output and at effects, persist required receipts through the real sink, then install a private exact grant in the SAME AuthorityOwner. Missing/ambiguous coverage or unavailable controller refuses. Remote admission remains Unsupported until that bridge and recognized remote issuer/proof routing are reviewed; do not call the local test profile remote Share/Sentinel complete. Crypto verification/signing remains in the existing central library/pin owners.

## 3. Proposed records: symbolic tags only until root freezes allocations

Caller-output, exact-length big-endian binary codec; no owned unbounded metadata or JSON. Proposed service prefix208 bytes:

| Offset | Field |
|---|---|
|0..4|root-approved service magic|
|4..6|schema version u16|
|6..8|root-approved symbolic variant tag u16|
|8..10|profile u16|
|10..12|flags u16, v1 zero|
|12..16|reserved zero|
|16..64|full descriptor StrongDigest48|
|64..112|full context StrongDigest48|
|112..120|publication generation u64|
|120..128|policy generation u64|
|128..136|cancellation generation u64|
|136..152|transfer/request ID16, nonzero and never reused within session|
|152..156|entry ID u32|
|156|representation class; initial plaintext only|
|157..160|reserved zero|
|160..168|representation epoch u64; plaintext0|
|168..176|leaf index u64, or variant-specific object offset|
|176..180|count u32; v1 leaf requests exactly1|
|180..184|body bytes u32, must equal exact remaining length|
|184..192|credit serial u64, checked nonwrapping|
|192..200|exact credited logical record bytes u64|
|200..208|accepted deadline Unix seconds u64|

Every unused variant field is canonically zero, not ignored. Header always carries selected expected descriptor/context/generation; no wildcard digest. Deadline is an upper bound only: host derives its own capped monotonic I/O deadline at admission and samples fresh trusted wall time for actual authority. Wire policy/cancel/credit values never mutate local canonical generations or enlarge limits.

Variant bodies proposed for approval:

* Describe request: fixed negotiated bounds record (max record/reassembly/metadata/index/entries/window/inflight and carrier mode); zero variable content. Response: one DescriptorPage object. Negotiate minima against actual admitted capacity before content. No privacy-sensitive catalog listing.
* DescriptorPage: fixed12-byte object selector: object class u8+three zero bytes, object/page number u32, exact total object bytes u32; then exact immutable object bytes. Classes cover body, detached publication proof, closure graph/manifest/proof, original header, suffix-index chunk, context page or entry page.64KiB is a page/body payload ceiling; proof-envelope transport ceiling96KiB is distinct from the actual existing cose envelope codec ceiling. Full original index can be bounded-chunked at64KiB, but decode still requires complete exact index and its independent resident admission. Page coverage/duplicates/global IDs checked by existing InventoryVerifier before a completed identity escapes. Cumulative8MiB descriptor metadata and1MiB/16-artifact closure ceilings remain separate and additionally included in one admitted bootstrap budget. Repeated identical already-accepted metadata is ignored only through the owner’s exact request/object state; conflicting bytes refuse.
* Select/Open: exact entry ordinal u32 and selected entry-page number u32, plus canonical requested profile/bounds; SelectedPlainEntry is constructed by the existing selection owner, never from caller-supplied root/length. Open acceptance returns Grant as protocol state acknowledgment with negotiated bounds; wire Grant does not grant local authority.
* Credit: no variable body; serial+bytes in prefix name ONE existing exact local admission and ONE response. RequestLeaves then consumes that serial for that exact leaf. Request and credit send failures do not release the actual reservation until unsent/queued/inflight state is drained. No additive credit counter that wraps or survives cancellation.
* LeafData: exact payload length u32 + exact encoded-proof length u16 + two zero bytes, then payload and proof. For plaintext payload<=16384, proof<=1537 (existing count-byte+32*48), prefix208+body8 yields maximum18137 bytes. Empty entries have no leaf request and are handled only by authenticated empty-root selection. Final short length is TreeSpec-derived, never peer-supplied permission. Proof decode into actual32 StrongDigest sibling scratch precedes verify_leaf/storage acceptance. No inline alternate root, signature or content key.
* Cancel, Outcome, Close: bounded fixed status/reason/generation detail, internal/public finite reason mapping; no arbitrary strings. Cancel never mints replacement credit. Outcome distinguishes received/integrity-staged from application/durable/economic acceptance; this package issues no durability/settlement claim.
* Resume: at most8 explicitly named missing leaf indices u64 with exact immutable identity/profile and fresh request IDs/credits. It is scheduling advice, not a bitmap/old permit/receipt import. New connection uses a fresh handshake/channel; no side effect or old credit replay. Recovery sources remain untrusted bytes reverified/re-written into current charged storage.

Exact magic/profile/tag/status allocations and variant fixed status/bounds layouts need root review BEFORE codec code. Proposed internal finite errors: Unsupported, Malformed, Limit, Capacity, State, Identity, Authority, Expired, Cancelled, StaleGeneration, Credit, Proof, Storage, Transport, WouldBlock, Closed. Preserve typed source errors internally; public refusal must not reveal object existence/private labels/key details.

## 4. Common channel, bounded assembly and credit ownership

Use the QBS10 consumed common endpoint/channel with ONE PacketProtection. Keep its fixed1024 plaintext-chunk geometry and canonical QFrame80, SessionDatagram/QSession, no extensions/QFrame fragment flag. Propose QBS09 RecordHeader88 with separate root-approved domain, transcript48, unique MESSAGE ID16, totalu32, offsetu32, chunku16 and finalu16. It is AEAD AAD. Message ID is a checked per-direction monotonic nonzero128-bit counter scoped to transcript/endpoint role; it differs from transfer ID because Credit/Request/LeafData/Cancel are different messages for the same transfer. QBS10 RecordHeader88 retains its private domain8192 cap. QBS09 complete service record limit is explicit negotiated prefix/body maximum (up to208+12+98304=98524), not an inherited8192 bound. Frame maximum80+88+8+1024+16=1216, fitting retained endpoint minimum1280.

Each record has exactly ceil(total/1024) contiguous chunks, offset multiple1024 and length min(1024,total-offset); exact final flag, no empty chunk, checked total/offset arithmetic/trailing refusal. A leased actual caller buffer backs the full negotiated record OR a reviewed incremental leaf sink; v1 choose the full record buffer and charge it before the first fragment. At most one current data assembly and one bounded control assembly per direction for the minimal profile; no table of partial uncredited messages. Unknown ID, uncredited first data fragment, duplicate conflicting fragment, interleaving beyond negotiated lane capacity or hole/out-of-order is terminal refusal. Packet replay is handled by the common owner; it does not authorize duplicate content commit. Control Cancel/Close has independent reserved bounded capacity and can interrupt partial data BETWEEN fully drained frames; an already partially written underlying stream frame must first drain through its actual owner or terminate. New message IDs increase monotonically per direction; the exact already-active data message may continue after an interleaved control message without opening an older new assembly. Discarded assembly is cleared/drained, not silently reinterpreted under a new request.

The common channel must retain exact sealed pending frame across WouldBlock, retry current authority before EACH send, advance cursor only on full accepted send, and treat partial send as terminal unless the actual bearer owns a reviewed bounded stream-write cursor. No resealing a retry/resetting packet counters, no payload copies outside admitted buffers. Receive authenticates packet and observed route before modifying assembly. Clear unaccepted plaintext assembly on all failures, cancellation, expiry and unwind. Plain public-candidate data still needs disclosure authority even though no object encryption is applied.

ReliableOrdered mode is admitted by the actual adapter/session owner, not a peer flag or BearerCapabilities.ordered alone. In that mode QBDL has no ACK/retransmission/congestion timer; native QSession/real reliable carrier owns recovery. Raw unreliable Ethernet needs its EXISTING QSession stream/loss/pacing owner composition and separate qualification; do not run reliable mode merely because a frame loopback is ordered. Loss or path change can fail closed/drain/reconnect; seamless migration is not promised. A changed observed route requires actual QSession/CSCP admission and renewed intent checks, never acceptance of a claimed wire locator.

Credit is a non-Copy local owner containing exact TransferTicket/CompletionKey/session/identity/leaf/serial/deadline/cancel fences. It is issued only after runtime admission covers network assembly + pending frame + verification proof/siblings + actual storage scratch + consumer capacity, and a fresh current authority check succeeds. Serialized credit is an authenticated peer instruction, not a reservation token accepted locally. Actual buffers and struct sizes, stack/crypto scratch and both queues are included; no multiplying budget by constructing another runtime. Endpoint retained charge and retained workspaces/sources reduce same-parent handle headroom before admission. Refusal happens before request or payload read. No credit reuse after a failure even if the wire bytes match.

Lifecycle: Selected -> Admitted/Queued -> Dispatched -> CreditIssued -> Requested -> Assembling -> Verified/Staging -> FinalChecked -> Draining -> Complete. Terminal Cancel/Expired/Revoked can start from every nonfinal phase. Page attempt stays armed outside the outer policy scope until native write and final runtime checks succeed. Actual I/O/borrow release and queued schedule drain precede complete_io; timeout does not prove no outstanding I/O. Lost owner retains charges and blocks close according to existing canonical semantics. Duplicate complete responses cannot run native storage/consumer commit a second time; request state becomes terminal before a further response is accepted. Durable/economic idempotence remains the existing application/receipt owner’s separate responsibility.

## 5. Provider/source and client boundaries

Proposed bounded ImmutablePlainProvider<'source,'metadata> privately associates actual immutable complete source, admitted original index, complete descriptor/candidate/BoundClosure, selected entry and retained exact metadata/outboard catalog. Construction runs existing full publisher/parsers/InventoryVerifier once under explicit cold budgets. Initial useful slice may use bounded caller-owned immutable RAM with no external writers; this is not a generic file snapshot claim. Larger files require a real excluded-writer snapshot/range source and quota-backed outboard lookup owner before claiming scalable provider storage.

Implement proof lookup in qbdl/provider/outboard.rs over TreeBuilder’s actual emitted (entry,start,count,digest) records, using existing tree split rule and proof codec, bounded32-node path and caller buffers. A cold bounded in-memory catalog is acceptable only within an explicit measured caller byte bound; disk outboards need a separately charged canonical backend extension and are not silently rebuilt per request. Validate assembled proof against actual leaf/root before send; actual source bytes read/hashed after blocking I/O and source generation checked. No second Merkle/hash primitive, full-bundle copy per request or static cached Allow flag. NativeSparseStore::read_verified_leaf can support a live verified provider only with its actual workspace/current grant/runtime/proof gate and honest integrity-only availability; checkpoint bits alone never serve bytes.

Client bootstrap retains charged complete immutable metadata/index/closure bytes and bounded scratch until actual InventoryVerifier and BoundClosure complete. A selected page alone is insufficient. SelectPlainEntry then supplies actual source mapping/root/length. For every leaf, stage uses current actual ticket, page and typed proof scratch, NativeSparseStore writes/proves/syncs through existing gates; failed/post-expiry effects poison/clear as the approved storage protocol requires. Serving or codec consumption is a fresh separately admitted effect. Existing directory-power-loss and process-restart limitations remain unchanged; this service cannot turn sync_all or a resume hint into a DurableVerifiedRange.

## 7. Acceptance tests and evidence limits

Pure wire/record tests: exact independent bytes; all variants/zero unused fields; maximum and+1 bounds; overflow/trailing; wrong descriptor/context/generation/ordinal/entry/representation; wrong final leaf length; empty entry; wrong page count/global duplicates/index digest; messageID vs transferID replay/counter exhaustion; stale/wrong credit, double Credit/Request/Response, overspend and credit after cancellation.

Actual owners: two independent managed endpoint peers and received-Finished installation, consumed channel cannot recreate packet owner, multiple different records have increasing packet numbers, WouldBlock retries identical sealed bytes, shared mutex gate does not relock/deadlock, foreign owner rejected, endpoint and content expiry/revoke/rotation at every pre/post I/O boundary, outer-final policy expiry after inner final success, canceled queued scheduler drain and late/double completion, lost owner blocks close, all admission rejects precede effects and do not leak. Raw assert_no_alloc_calls with positive control on real codec/credit/dispatch/receive/verify paths, warmup outside measure; no global test allocator invention.

Provider/storage: independently generated multi-leaf outboard proof vs actual publisher bytes/root; corruption/stale snapshot/read failure/proof sink unwind; selected partial object into actual canonical range staging, sync/checkpoint fault boundaries and no holes-as-zero; canceled/expired paths clear unaccepted assembly/page and retain actual I/O charge until drain. Useful leaf/tail transfer while unrelated payload remains unrequested. Storage resume/recovery reverify actual bytes, not checkpoint trust. No duplicate codec/consumer commit; no transport ACK interpreted as durable acceptance or payment.

Qualification requires actual two OS processes over reviewed native bearer with HTTP/DNS/IP sockets/libp2p disabled, finite watchdog and recorded platform/bearer/security class. Exercise induced partial read/write, frame corruption/replay, disconnect/reconnect missing-ID resume, refused path substitution, revoke mid-transfer and bounded cancellation/control progress. Report Linux AF_PACKET privilege refusal, Windows restrictions and unavailable carriers as unsupported/untested, not success. In-process queue and Unix8-byte process harness do not satisfy QBS09/G01. Physical cross-host flags remain separate. No new runtime/backend/crypto execution or G01 qualification was performed for this report.
