Required runtime contract

One contract, from authoring to validated output

VibeScript profile → Conditioning ontology / Aura–SHACL → core compilation → typed roles and evidence → model template and exact tokens → memory admission → prefill / decode → output validation and receipt

  1. Compile and check authority. Reuse conditioning::compile_into and caller-supplied buffers. Inspect every requirement outcome; a summary is not proof of runtime enforcement. VibeScript and ontology tags cannot grant access.
  2. Prepare an immutable request. Snapshot profile ID/version/spec, model and template identities, selected evidence and authority. Keep instructions, user content, history, tools and untrusted evidence distinct until supported backend lowering.
  3. Budget the actual request. Include template delimiters, tool schemas, special tokens and expanded multimodal input. Keep mandatory requirements and the complete user request; reject an impossible budget instead of silently trimming them.
  4. Attach only compatible state. Match exact token prefixes plus checkpoint, tokenizer, template, adapter, policy, access scope and state layout. Hybrid models need attention KV and recurrent/convolution state at the same committed boundary. A stable header alone is not cache validity.
  5. Preserve controls during execution. Batching and offload keep each request's grammar, sampler, output reserve, cancellation and Sentinel gates isolated. Streaming output remains provisional until validation; inference success is not a graph-write authorisation.
  6. Report and roll back explicitly. Separate inference, validation, persistence, provenance and usage status. A missing optional calibration profile uses the governed base route; an incompatible required contract fails closed.
actual_input_tokens ≤ profile.input_tokens
actual_input_bytes ≤ profile.max_bytes
actual_input_tokens + reserved_output_tokens ≤ supported_context_tokens
planned KV + recurrent state + scratch + resident weights ≤ device budget
host expert banks + pinned staging + other host state ≤ host budgets

These are implementation requirements, not guarantees supplied by the current byte-based lowerer. The same final token IDs must be counted and executed. Tool and repair rounds share cumulative limits; output reserve is not part of input-token usage.

Required capability target · not yet demonstrated in QualiaDB

Qwen3.6-35B-A3B NVFP4 on RTX A2000 12 GB

The inference renewal requires full-model loading, prefill and generation on the user's A2000, with measured reference-equivalent or better capability. It does not require all weights to reside in 12 GB of VRAM: compressed host expert banks, bounded GPU slots and transfer scheduling provide the necessary memory hierarchy.

The target needs Qwen's actual hybrid attention and recurrent state, expert routing, shared experts, mixed quantisation formats and an Ampere-compatible dequantisation path. NVFP4 checkpoint storage must not be confused with a requirement for native FP4 hardware. Prompt compaction can reduce input work; it does not replace weight offload.

Acceptance compares the same checkpoint, prompts, context, output reserve, modality and concurrency. Record cold load, TTFT, prefill/decode throughput, tail latency, host/VRAM peaks and held-out quality. Loading alone, shorter answers or a silently reduced context do not establish parity. Other model and multimodal capabilities need their own explicit validation rows.

Measured promotion

Evaluate real outputs before activating a profile

Isolate evaluation splits

Search on train/dev tasks. Evaluate the selected profile and baseline on sealed held-out tasks with independent validators. Expected answers never enter model input; simulated runs cannot authorise production promotion.

Measure quality and resources

Report task success, required constraints, evidence and tool correctness, actual tokens, cold/warm latency and peak memory. Compare equal-budget and full-context conditions separately; cache benefits are distinct from prompt-quality gains.

Bind and verify promotion

Extend signed receipts to bind the complete checkpoint manifest, template, backend/hardware, corpus and real measurements. Promote only after quality/resource gates pass; retain a verified rollback profile and invalidate incompatible caches.

Bounded execution, honest capability reporting

Tier-1 evaluators and ABI-crossing buffers use caller-owned storage and must pass real zero-allocation tests. Cold authoring and request assembly may use explicitly bounded construction. Preserve the 48-byte NQuin ABI and the 42 MiB Sentinel execution arena; model weights, KV, pinned host memory and VRAM require separate governed budgets, not a claim that the whole model fits the Sentinel.

Learned prompts, layer prefixes and LoRA remain separately gated experiments. They need shape compatibility, measured application costs and held-out gains over the best text baseline. No learned-adapter result or automatic calibration gain is asserted here.
