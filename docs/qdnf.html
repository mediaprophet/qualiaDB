A network that does not borrow DNS to know a human.

The Qualia Decentralized Network Fabric (QDNF) is QualiaDB’s native networking architecture. Inside a QDNF realm, peer discovery, routing, session encryption, and .q42 knowledge replication operate without ARP, IPv6 neighbour discovery, DHCP, ICANN DNS, BGP, or mandatory cloud relays. The Qualia Peer Runtime (QPR) is our bounded, zero-heap-hot-path peer engine over that fabric — engineered as a ground-up replacement for libp2p, never a wrapper around it.

Release 0.0.41 Verification Scope: QDNF separates human identity from network routing across three strict Identifier Fabric planes. In-tree protocol engines (NET-18 through NET-21 and EVAL-22), the QPR connection manager, CSCP local control-plane slices, did:qi pairwise relationship lifecycle, and named Transition bearers (WireGuard, TLS WebSocket, HTTP/2 Extended CONNECT capsules, and Nym mixnet framing) are verified in tree. Public Internet relay and MASQUE qualification flags remain false until multi-host public endpoint trials are executed. The earlier Network Webizen console remains an interactive topology preview.

Handle ≠ human. Protocol surfaces distinguish the human (NaturalAgent) on the Entity plane from expiring locators on the Handle plane and cryptographic channels on the Instrument plane. Law keeps the word person where statutes require it.

Layer 1 · Plain-Language Overview

Why QDNF Exists: Separating Entity, Handle, and Instrument

Legacy Internet protocols conflate who participates with where packets travel. When an ICANN domain expires, an IP prefix shifts in BGP, or a cloud relay closes an account, applications treat the underlying human or community as erased. QDNF eliminates that fragility by splitting identity, addressing, and transport into three non-overlapping planes:

1. Entity Plane (Who)

Sovereign Human & Community

Represents the natural person (NaturalAgent) or ratified multi-party agreement (did:webizen). Entity identifiers never appear in wire routing headers, carrier lookup tables, or public DNS zones.

2. Handle Plane (Where)

Expiring Topological Locators

Self-certifying, time-bounded network locators (DNI), optional DNS handles, and carrier hints. Handles exist solely to forward cells across links. Handle revoke ≠ who-erase: revoking a locator closes a route while preserving local .q42 knowledge volumes.

3. Instrument Plane (How)

Pairwise Channels & Cells

Cryptographic instruments including pairwise rotating did:qi relationship documents, CSCP control mailboxes, QSession encrypted streams, and supervised QPR Network Cells with strict byte budgets.

What the six QDNF layers do

QLink
Cryptographic link adjacency and bounded QFrame wire framing over local IPC, native links, or explicitly labelled Transition bearers.
DNI
Self-certifying, expiring topological locators on the Handle plane — never a permanent identity or unrevokable profile.
QRoute
384-bit radix-16 Qualia Semantic Routing (QSR) with RarPermit binding and Bellman–Ford primal-dual shortest-path optimality verification.
QResolve
Deterministic resolution for did:qi, did:webizen, and did:q42 resource coordinates without ICANN DNS-as-identity.
QPolicy
Deontic capability gates and a 40-scenario confidentiality lattice emitting parity-checked NQuin egress audit receipts.
QSession / QSync
Authenticated CSCP and QSession streams with SHA-384 transcripts, HKDF-SHA384 directional keys, and .q42 SuperBlock synchronization.

Architectural Non-Goals

What QDNF is not

  • Not a browser packet sniffer: Static GitHub Pages documentation cannot inspect host NIC rings or forge live network telemetry.
  • Not identity-by-locator: Locators, sessions, and did:qi instruments remain off the Entity plane. Handle revoke ≠ who-erase; human (NaturalAgent) ≠ legal “person” ≠ software bot.
  • Not DNS-as-who: Losing a domain name or IP lease never invalidates a human’s .q42 knowledge graph or did:webizen agreements.
  • Not carrier laundering: Wrapping a QFrame inside Transition bearers (WireGuard, WebSocket, HTTP/2, or Nym mixnet framing) does not upgrade the path to Native Independent or launder proxy authenticity (no_proxy_launder).
  • Not an unverified public cloud claim: See the QDNF implementation status for the exact boundary between in-tree verification and external Internet trials.

Layer 3 · Cryptographic & Routing Mechanics (0.0.41)

Completed In-Tree Protocol Engines (NET-18–NET-21 & EVAL-22)

Release 0.0.41 completes five foundational cryptographic, routing, replication, policy-audit, and tri-source qualification packages inside crates/qualia-core-db/src/net/ and crates/qualia-cscp/, adhering strictly to the Zero-Heap hot-path and 48-byte NQuin parity contracts.

NET-18 · Session & CSCP session/handshake.rs · rekey.rs · bind.rs

CSCP Handshake, HKDF-SHA384 & Locator Binding

Establishes HandshakeTranscriptDigest as a deterministic SHA-384 digest over ClientHello || ServerHello || NegotiatedParams. Directional session keys are derived via HKDF-SHA384 and rotated through generation-monotonic rekey_session transitions that zeroize retired key material.

Enforces LocatorBinding with the no_proxy_launder invariant: frames arriving via a proxy or transition relay can never upgrade AuthenticityClass to native direct peer authenticity.

NET-19 · QSR & QRoute qsr/exact.rs · route/spf.rs

384-Bit Radix-16 QSR & Dual Shortest-Path Witness

Implements full 384-bit (48-byte / 96-nibble) radix-16 trie lookup in qsr/exact.rs coupled with cryptographic RarPermit capability verification before forwarding.

Pairs intra-realm route planning with verify_spf_dual_optimality: a Bellman–Ford primal-dual witness verifier that checks dual triangle inequality (d[v] <= d[u] + w(u,v)) across all admitted edges alongside a loop-free predecessor tree witness.

NET-20 · QSync & QPR Leases replication/ · runtime/ledger.rs

Chunk-to-SuperBlock .q42 Replication & Lease Accounting

ChunkToSuperBlockManifest bridges SHA-384 transport chunks to SHA-256 .q42 v4 SuperBlocks, verifying 5-field NQuin XOR parity (subject ^ predicate ^ object ^ context) on every datum prior to commit_verified_block.

Coupled with release_checked_bytes in the QPR ReservationLedger, ensuring byte-budget reclamation verifies lease generation counters and fails closed on stale or double-released handles.

NET-21 · Egress Governance policy_labels/egress.rs

40-Scenario policy_labels Egress Admission Matrix

Evaluates outbound transfers across all 40 combinations of confidentiality tiers (C0Public–C3Restricted), restriction bitmasks (NO_TRAINING, NO_EXTERNAL_AI, NO_PUBLIC_INDEX, NO_REDISTRIBUTE, NO_BIOMETRIC_REUSE), and caller classes (Vibe, Poet, BackgroundWorker, DelegatedTool).

EgressAuditReceipt and enumerate_egress_audit_quin emit 5-field parity-verified NQuin audit records for every admission or denial decision.

EVAL-22 · Tri-Source Evaluation Aggregator .q42 v4 Qualification Plane

Unified Etalon + QDNF + QualiaDB Qualification Receipts

EVAL-22 combines three independent verification streams — Etalon deterministic oracle receipts, QDNF network transport/routing receipts, and QualiaDB core arena invariant receipts — into a unified .q42 v4 qualification record reporting exact passed, failed, and unsupported counts per plane without conflating local proof with unexecuted hardware or public-Internet gates.

Layer 4 · Verification & Qualification Boundary

0.0.41 Networking — What Runs vs. Open Qualification Gates

Every capability is classified by its concrete verification boundary: in-tree verified modules, platform-gated hardware paths, and multi-host public-network gates.

Local & In-Tree Verified

  • QPR connection manager in tree: policy lattice, dual-stack path planner, capability invitations, and durable delivery pairs.
  • CSCP local control plane (qualia-cscp): fail-closed TLV codec, private mailbox, generation leases, receipts, loopback bound-UDP, and local rustls WebSocket (WSS) ↔ QSession.
  • CSCP-09.01 / 09.02: local DATAGRAM capsules and loopback HTTP/2 Extended CONNECT proof paths.
  • did:qi: signed QCDE-1 document lifecycle, CscpMailbox binding, relay-only refusal of direct locators, and Direct-permitted path selection.
  • Transition bearers: WireGuard overlay, TLS WebSocket, HTTP/2 capsules, and bounded Nym mixnet framing.

Qualification Holds (Platform)

  • Raw Ethernet & AF_XDP: open_af_xdp fails closed with PlatformUnsupported on unprivileged userspace; umem_registered() and silent_zero_copy_fallback() report false until dedicated NIC ring hardware is attached.
  • Multi-cell scaling telemetry: 1–16 cell fair-share admission and RSS/NUMA sampling run in tree; hardware RAPL idle-joule certification remains held on physical sensor access.
  • Static Pages boundary: GitHub Pages publishes deterministic architecture and test records for tag v0.0.41 (0.0.40 archive retained) but cannot execute live socket capture.

Public-Network & Standards Gates

  • CSCP-08 (Two-Host Public Relay): Public Internet WSS / MASQUE relay trial requires an externally reachable second host. public_relay_dialed() remains false.
  • CSCP-09 (Live Internet MASQUE): Loopback HTTP/2 Extended CONNECT is verified in tree; live Internet MASQUE and QUIC/noq carrier qualification remain open.
  • CSCP-12 (IETF Datatracker): Working draft draft-webcivics-cscp-00 is prepared in repository; external IETF Datatracker posting is an explicit human standards gate.

Continuity Invariant · Active

Handle revoke ≠ who-erase

ABN numbers, DNS domain names, state registry strings, and transport locators sit strictly on the Handle plane — never on the human (NaturalAgent) Entity plane. A sovereign agent and its local Sanctuary Keep volumes persist independently of any external registrar.

Revoking or rotating a handle closes or holds that network locator while keeping the human’s cryptographic history and .q42 knowledge base intact.

CSCP-08 & CSCP-12 · External Gates

Public Internet MASQUE & Standards Boundary

Local WebSocket (WSS) and loopback HTTP/2 Extended CONNECT slices execute deterministically in tree. Completing CSCP-08 requires a two-host trial across a live public Internet endpoint, so public relay evidence flags remain false until that trial runs.

Similarly, CSCP-12 (IETF Datatracker submission) and W3C DID Spec Registries enrollment are tracked as external standards gates, never auto-claimed by local test suites.
