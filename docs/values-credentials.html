How it stays fast & honest

  • One 60-bit hash space. q_hash ≡ generate_60bit_token; the top 4 bits are a tag/modality overlay. Closed datatypes inline; open identifier-kinds resolve as modal predicates.
  • Zero-alloc resolution. The per-cell QuinIndex yields 48-byte NQuins by copy — point lookups with no heap churn in the hot path.
  • Multilingual base. Every natural-language literal is @en-flagged (BCP-47); other languages attach as additional @lang literals on the same subject.
  • Verified, not asserted. All — volumes round-trip: — triples in, the same read back.

Verifiable Credentials runtime

ML-DSA-65 · fail-closed

A credential is a signed set of claims bound to an identifier — it is not identity. Identity is the relational structure built over a fabric of identifiers (machine proposes skos:closeMatch; a signed human ratifies skos:exactMatch; never fully resolved). Verifiability authenticates a claim's origin, not its truth: a perfectly-signed credential can still be false-in-fact, so credentials enter the same divergence-preserving machinery as any other evidence — held alongside contradicting records, never auto-promoted to fact. (Lineage: W3C Credentials CG → Verifiable Claims → VC Data Model.)

Wired today
  • issue / present / verify over the W3C VC Data Model (@context, type, issuer, credentialSubject, proof).
  • Real ML-DSA-65 (FIPS-204) signatures via fiduciary_crypto.
  • Fail-closed verification: missing proof, tampering, or a bad signature return an error — never a silent true.
Codecs & access
  • OpenBadge v3 and PDF codecs over one unified Credential type.
  • Access-tier gate (AccessModality / DataTier): can_access(tier, is_verified) fails closed on an unverified holder.
Planned (not yet wired)
  • Holder storage — hold() is a no-op placeholder.
  • Status / revocation — StatusResult exists; the status-list check is not wired.
  • Selective / ZK disclosure — the engine has real Groth16 (zk_proofs) to build on; not yet bound to VC presentation.
Rust API — crates/qualia-core-db/src/identity/credentials/
let runtime = VcRuntime::new(fiduciary_crypto);

// Issuer signs a credential (ML-DSA-65)
let signed = runtime.issue(credential, Some("issuer-key"))?;

// Holder bundles credentials into a signed presentation
let vp = runtime.present(vec![signed], Some("holder-key"))?;

// Verifier checks origin — fail-closed (Err on tamper/missing/bad-sig)
let ok: bool = runtime.verify_presentation(&vp)?;

// Tiered access gate (fails closed for an unverified holder)
AccessModality::Read.can_access(DataTier::Sensitive, is_verified)?;

Rust API today; not yet exposed through the WASM bridge, so there is no in-browser demo on this page.
