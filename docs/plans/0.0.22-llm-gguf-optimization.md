# 0.0.22 LLM/GGUF optimization record

## Measured baseline

Hardware: NVIDIA RTX A2000.

| Model | Quantization | Throughput | Time/token | Main bottleneck |
|---|---:|---:|---:|---|
| SmolLM2 360M | Q8_0 | 17.51 tok/s | 57.1 ms | attention 62% of forward |
| Llama 3.2 3B | Q4_K_M | 4.09 tok/s | 244.7 ms | attention 68% of forward |

Llama forward compute consumes 94% of token time. GPU fence overhead is about 4–6%, so this
workload is kernel-bound rather than submission-bound.

## Decisions implemented

- The native resident-decode experiment was removed. It duplicated approximately 700 lines of
  attention/FFN encoding and measured 17.20 tok/s versus 17.51 tok/s on the canonical path,
  despite reducing GPU waits from 107 to 44 per token.
- STEM and logic capabilities now use one structured registry mapping each capability to the
  existing MCP solver tools. Chat briefing and MCP registration are parity-tested against it.
- The registry now includes concrete operation groups, maturity, and runtime surfaces for the
  broader solver library. `list_capabilities` exposes the same catalogue over MCP with optional
  domain/maturity/surface filters. Internal-only functions remain discoverable without being
  misrepresented as remotely callable; unavailable façades such as specialized ML inference are
  explicitly labelled `fail-closed`.
- `C:\LLM_Models` is the preferred Windows model vault. The CLI performs a read-only,
  size-bucketed SHA-256 duplicate audit; it never copies, moves, or deletes models.

## Model storage audit

Ten GGUF/mmproj artifacts occupy about 25.84 GiB under `C:\LLM_Models`. Three SmolLM2 Q8 files
are byte-identical (SHA-256
`48ab3034d0dd401fbc721eb1df3217902fee7dab9078992d66431f09b7750201`).
Keeping the root-level file would make 737.0 MiB reclaimable. No files were changed.

Run:

```text
qualia-cli llm duplicates --vault-path C:\LLM_Models
```

## Next performance work

1. Instrument Q/K/V/O projection time separately from SDPA inside the attention total.
2. Optimize whichever side dominates; do not add another decode implementation.
3. Move native inference to a long-lived worker that owns one `QTensorEngine`, so repeated
   prompts reuse pipelines and model placement. This targets first-token latency, not tok/s.
4. Re-run the same two baselines after every change and reject noise-level or regressive paths.
