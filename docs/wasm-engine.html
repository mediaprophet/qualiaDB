v0.0.41 Release Prep · v0.0.40 Baseline

Unified WASM Volumetric & Etalon-WASM Pipeline

wgpu 30.0.0-etalon · wasm32-unknown-unknown

Building upon the 0.0.40 production baseline, the 0.0.41 release unifies the graphics and compute runtime across native desktop and browser targets. webizen-render volumetric rendering modules compile directly to wasm32-unknown-unknown, while webizen-web (qualia-wasm) introduces two-tier rendering (Hardware WebGPU Volumetric + Deterministic Canvas2D fallback) paired with etalon-wasm worker telemetry.

webizen-render on wasm32-unknown-unknown

Direct WebGPU compute and volumetric raymarching now runs natively in browser contexts without desktop-only stubs:

  • VolumetricRenderer::from_canvas(canvas, cap): Configures a hardware WebGPU PortalGpu surface directly on an HtmlCanvasElement with capability-intersected adapter limits.
  • VolumetricRenderer::render_scene_frame(scene, camera): Zero-heap per-frame upload of 10D node tensors (Tensor10D) and colored scene meshes from a RenderScene.
  • volumetric_hmc: Hamiltonian Monte Carlo volumetric sampler compiled to WASM for continuous probability distributions.
  • volumetric_texture: Direct 3D density texture sampling and hardware filtering on browser WebGPU devices.

webizen-web (qualia-wasm) QualiaPortal

Dual-tier rendering architecture ensures universal compatibility from high-end WebGPU rigs down to restricted software canvases:

  • Tier 2 Hardware WebGPU: await portal.init_webgpu(canvas) initializes GPU volumetric pipelines, marks WorkerSteward ready, uploads cached tensor state, and renders the active RenderScene.
  • Tier 1 Deterministic Canvas2D: SimpleCanvasRenderer::render_scene(scene, yaw) provides mathematical Canvas2D fallback, projecting and drawing translucent faces, directed edges, and labeled nodes before overlaying the HUD.
  • etalon-wasm WorkerSteward Telemetry: Live inspection via portal.etalon_transport_mode(), portal.etalon_worker_state(), and portal.etalon_session_generation().

Browser WebGPU Volumetric SDK & Fallback Usage JavaScript / TypeScript 
import init, { QualiaPortal } from './pkg/qualia/qualia_wasm.js';

await init();
const canvas = document.getElementById('qualia-viewport');
const portal = new QualiaPortal(canvas);

// 1. Inspect Etalon-WASM transport telemetry
console.log('Transport mode:', portal.etalon_transport_mode());      // "SharedArrayBuffer" or "TransferableMessage"
console.log('Worker state:', portal.etalon_worker_state());          // "Ready" | "Standby" | "Initializing"
console.log('Session gen:', portal.etalon_session_generation());     // Generation epoch for recovery

// 2. Load cross-platform RenderScene contract (or 10D tensor manifold)
portal.load_json_scene(JSON.stringify(renderSceneContract));

// 3. Attempt Tier 2 WebGPU upgrade (seamless fallback to Tier 1 Canvas2D on older hardware)
try {
  const tier = await portal.init_webgpu(canvas);
  console.log('Hardware WebGPU Volumetric active (Tier 2):', tier);
} catch (err) {
  console.info('Falling back to deterministic Tier 1 Canvas2D scene + HUD renderer:', err);
}
