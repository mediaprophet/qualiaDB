Why VibeScript? A semantic execution layer

VibeScript is for programs whose data meaning, authority, and replay semantics are part of the product. It does not ask a browser runtime to infer those boundaries from ad-hoc objects, network calls, and framework conventions.

VibeScript (or Vibe) is the native scripting layer of QualiaDB and the Poet creative environment. It is an interpreted, typed, capability-bounded language engineered with zero heap allocations in hot paths, first-class RDF 1.2 and SPARQL semantics, verifiable deontic norms, and deterministic execution for eligible programs. JavaScript remains useful for conventional DOM integration and its broad web ecosystem; Vibe supplies the semantic and authority-bearing layer beneath a UI.

Role 01

Reactive Cell Graphs

Pure, high-frequency formulas driving desktop UI manifolds and QApps. Cells form dependency DAGs with bounded evaluation and strict cycle detection. Performance depends on the selected target and workload; the important invariant is that the hot evaluator does not allocate.

Role 02

Signed Agent Modules

Cryptographically signed programs that query and mutate knowledge graphs. Every external capability (graph query, network pulse, sensor feed) requires an explicit lease grant and execution route, allowing a host to deny or diagnose unavailable authority.

Role 03

Deontic & Event Hooks

Deterministic lifecycle handlers like on pulse:message(...) and on tick(). Prohibitions and obligations can be checked against the QualiaDB logic surface; host effects remain explicit rather than being silently substituted in a standalone browser target.

Where Vibe fits beside other runtimes

Vibe is not a universal replacement for JavaScript, Python, Lua, or embedded Rust interpreters. Its advantage appears when a program needs a typed semantic graph, declared authority, Q42 portability, or an auditable execution boundary.

VibeScript 0.1 Feature Highlights

✨

Workshop Dialect

Human-friendly syntax using Animation; with clean method calls like Animation.orbit_spin(t). Unleased method paths fail closed at check-time.

🔗

Two-Way Data Binding

Native bind slider <-> volume using Clamp[0.0, 1.0] resolve latest; keeps reactive states synchronised across UI widgets.

⏱️

Temporal Tweens & Springs

First-class interpolation with 0.0 ~ 10.0 over 400ms ease linear and dynamic physics dampening via spring(stiffness, damping).

λ

Pure Non-Capturing Lambdas

Lightweight |x| expr pipelines for transformation like [1, 2, 3].map(|x| x * 2).filter(|x| x > 2) with zero closure escape overhead.

📜

Ontological Vocab Chunks

Load domain ontologies (SNOMED, QUDT) as tree-shaken .n3 dependency chunks. Canonical IRIs are preserved with zero string table bloat.

🎨

Presentation Sheaves

Declare multisensory visual entities with present lamp { color: glow, pose: pose }, mapping directly to WebGPU viewport pipelines.

🌏

Multi-Lingual Identifiers

Support for Chinese (locale zh;), Cyrillic, and Arabic identifiers. Golden CBOR-AST hashing guarantees identical execution across all locales.

🛡️

Deontic Norm Enforcement

First-class obligate, permit, and forbid operators evaluate against the verified deontic engine, securing autonomous agent actions.

⚡

Stack Bytecode VM

VBC1 stack-based bytecode compiler and VM with 35 opcodes for instant zero-copy serialization and deterministic sandboxed execution.

Canonical VibeScript Demos

Explore real VibeScript programs demonstrating reactive graphics, two-way bindings, and clinical knowledge graphs:

1. 3D Manifold Animation & Presentation Sheaf

using Animation, HID;

// Reactive cells stepping on live temporal ticks
effect cell t := time.now();
cell pose := Animation.orbit_spin(1.0);
cell glow := oklch(0.72, 0.12, 230.0);

// Declarative visual surface present block
present lamp {
    color: glow
    pose: pose
}

2. Two-Way UI Data Binding with Clamp & Resolve

let mut volume = 0.2;
let mut slider = 0.2;

// Two-way reactive bind with bounding clamp
bind slider <-> volume using Clamp[0.0, 1.0] resolve latest;

fn main() -> f64 {
    // Temporal tween easing
    return 0.0 ~ 10.0 over 400ms ease linear;
}

3. Clinical Knowledge Graph & Tree-Shaken SNOMED Vocab

prefix snomed: <http://snomed.info/id/>;
using GraphDatabase;

// Tree-shaken vocabulary query resolved against bounded clinic chunk
pure fn get_diagnosis() -> Iri {
    return snomed:386661006; // Fever (finding)
}

fn main() -> Iri {
    return get_diagnosis();
}
