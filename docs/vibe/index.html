What is VibeScript?

VibeScript (or Vibe for short) is the scripting language of the QualiaDB semantic engine. It is designed for three roles:

  • Reactive cell formulas — pure expressions like = math.max(0, math.min(100, score)) that drive HCF/QApp cells
  • Signed document/agent modules — programs that query and transact on a graph snapshot with full capability enforcement
  • Host event handlers — on pulse:message(...) and on tick() hooks dispatched by the Poet engine

VibeScript is not a JavaScript clone or a general-purpose language. It is a closed, typed core with no eval, no DOM, and no JIT — making it safe for sandboxed execution, deterministic replay, and edge deployment.

🔒

Capability-Bounded

Every effect requires an explicit capability grant. Scripts cannot access the graph, network, or sensors without declared permissions.

⚡

Bytecode VM

Optional stack-based bytecode (vibe-bc-0.1) with binary encode/decode for fast pre-compiled execution.

📐

Typed

Static type checking with i64/u64/f64/string/bool, Result/Option, lists, records, IRIs, and domain types (Instant, Quantity, Field, Material, Law).

🌐

RDF-Native

First-class RDF triples, reified triples, prefixed names, blank nodes, and graph queries built into the language.

🧪

Physics & Spectral

Built-in wrappers for wave equations, thermodynamics, EMF-to-color, spectral blending, and gamut mapping.

🌍

Multi-Lingual

Unicode identifiers with BiDi isolation, homoglyph detection, and keyword locale tables (English + Chinese).

⏱️

Temporal Honesty

First-class Instant, Duration, and proper-time types. No raw Unix timestamps — time has scale, frame, and optional seal.

🛡️

Deontic Logic

Obligation, permission, and prohibition as first-class values. Prohibition breach produces a sealed receipt, not a crash.

🤖

Agent Orchestration

DAG pipelines, multi-agent blackboards, semantic skills, and reflection loops for autonomous agent scripting.

Example: Signed Module

module <https://qualiadb.org/modules/clinic_alerts>;
prefix clinic: <https://qualiadb.org/clinic/>;

requires [
    capability("graph.read", context: clinic:telemetry),
    capability("graph.write", context: clinic:alerts),
    capability("pulse.publish", topic: "clinic/alerts")
];

effect fn raise_alert(sensor: Iri, value: f64) budget(steps: 20000) -> Result<Receipt, string> {
    if value <= 85.0 {
        return Ok(receipt_empty());
    }
    let stated = << sensor clinic:emitsAlert clinic:Overheat ~ clinic:claim_1 >>;
    transaction {
        graph.stage(stated);
        aura.validate(clinic:claim_1, clinic:EmergencyAlertShape)?;
        graph.commit()?;
    };
    effect pulse.publish("clinic/alerts", { sensor: sensor, value: value })?;
    return Ok(receipt_empty());
}
