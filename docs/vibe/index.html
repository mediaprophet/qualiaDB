Vibe / VibeScript

Poet is the engine. Vibe is the language. This hub is what should be published for humans and agents. Language version vibe-0.1. Not v1.0 until core §15 holds.

Read in this order

  1. vibescript-core.md — normative 0.1 grammar, types, effects, bindings
  2. vibescript-specification.md — architectural essay; not the parser contract
  3. AI agent readiness — ontology / GBNF / corpus / diagnostics overlay
  4. poet-vibe rustdoc — after workspace rustdoc is on Pages

Agent artifacts

  • SKILL.md — what coding agents should load
  • poet_vibe::diagnose(src) — JSON diagnostics + safe suggested_fix
  • CapabilityDiscovery.catalog — Turtle of live bindings and invoke ids
  • poet-vibe/grammar/ — EBNF, GBNF, JSON Schema

Workbench vocabulary

poet-ui-concepts.md — manifolds (surfaces), tool chest (holds toolboxes of tools), containers (occupants). HTML/GPU canvas stays a drawing surface.

Runtime

  • capability.invoke — engine families; CapabilityDiscovery.coverage lists bound vs unbound
  • GraphDatabase.sparql / SHACL.validate — graph + SPARQL-star + extension catalog
  • Desktop Poet harness: View → Shell: Poet → /poet (Classic stays default)

How this gets published

These files live under docs/. GitHub Pages (Jekyll) deploys that tree from main / 0.0.30 via .github/workflows/pages.yml.

  • Do not point Pages at 0.0.31-dev wholesale — that would replace the production playground.
  • To ship this hub: merge (or cherry-pick) docs/vibe/ + the manuals above onto the Pages branch.
  • NLP TechDesign stays the authoring copy; product tree is what Pages serves.
