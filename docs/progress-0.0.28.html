Honest progress — 0.0.28

This page is for operators and reviewers who need the truth, not a launch brochure. QualiaDB is the semantic engine; Webizen is the habitat product shell. Where we are not yet good enough for life-critical sole reliance, we say so.

What 0.0.28 is for

Make the desktop understandable and observable: guided setup for ordinary use, an Advanced Technical mode, visible background work, exportable diagnostics, restored communications, and a Hypermedia library that acts as the semantic home for documents, ontologies, models, and graph-derived artefacts. The same release also aligns every workspace crate and web package to 0.0.28.

This is an integration release, not a claim that every deep engine capability is now equally discoverable.

Not good enough yet (as sole system)

  • Desktop installers / signed updater CI is still hardening — do not treat a failed Actions run as a silent success.
  • Local LLM decode on large models is not yet competitive with specialised CUDA stacks for latency-critical use.
  • Do not use free-form generation alone for high-stakes legal, medical, or safety decisions.
  • Native mobile apps are out of product scope; phone = installable remote controller PWA only.
  • GPU capability profiling is diagnostic-only; runtime feature negotiation is not yet wired into all render paths.
  • Mixed-quant “Q4_K_M” browser models remain gated: native decode is coherent and the browser Q5_0 GEMM oracle passes exactly, but the specialised fused Q5 FFN path is still under end-to-end certification.

What is real in 0.0.28

  • Job Centre and debug mode — long-running downloads, model loads, anatomy assets, parsing, conversion, and inference are represented as jobs with state, progress, cancellation, retry, and failure details. Desktop logs are structured and exportable for agent-assisted diagnosis.
  • Setup and operating modes — the first-run flow captures local storage, identity, model provider, privacy, networking, ontology packs, accessibility, and optional social services. General mode uses task language; Advanced Technical mode exposes backends, graph details, hashes, manifests, and diagnostics.
  • Hypermedia semantic explorer — documents, ontologies, model packages, graph records, provenance, and derived artefacts share a navigable library. Ingest jobs expose parse, classify, map-to-ontology, validate, and graph-write stages.
  • Communications, Chora, and anatomy — chat, contacts, and social-web reception return to desktop navigation; Chora links are actionable; anatomy asset acquisition is a visible background job rather than an indefinitely waiting screen.
  • Agent-callable quant diagnostics — the browser harness runs a deterministic WebGPU-to-CPU projection check. The tested SmolLM2 Q5_0 projection passed with maxAbs=0 and maxRel=0; the SOA package remains gated after failing this oracle.
  • WASM feature profile fixes — portal, wasm-logic, wasm-scientific, and wasm-llm all compile and link under wasm32-unknown-unknown. The portal slim bundle and the full playground bundle are both green in CI.
  • Native shader emitters — WGSL Forge now emits typed kernel/schedule IR with Naga validation, CPU oracle, and real GPU timing. Adapter-keyed cache for deterministic generation/certification/tuning.
  • Knowledge universe surface — universe.html renders the bundled corpus as galaxies (Schema.org, FIBO, W3C, GeoNames, CODATA constants) with a Chora Yale bright-star celestial layer. Drag, zoom, click.
  • GPU capability profiling — shared wgpu 30 device with capability-intersected f16/subgroup/timing features. Tensor10D projector, depth/bloom/mesh/picking, caller-buffered RGBA8.
  • Workspace crate bump — all workspace crates bumped to 0.0.28; portal package.json version aligned across pages.yml and release-wasm.yml.
  • Engine base (carried forward) — 48-byte NQuin, 42 MB Sentinel, modalities (deontic, epistemic, LTL, ASP, …), native GGUF/P64 + wgpu inference, SPARQL/N3/SHACL paths, vision/audio crates, privacy BFV/DP.
