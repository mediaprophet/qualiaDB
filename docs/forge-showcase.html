WGSL Forge

A deterministic GPU-kernel compiler, Naga AST validator, and CPU-oracle correctness certifier powered by etalon-wgsl-forge. It lowers typed KernelSpec + Schedule graphs into multi-backend shaders without LLM heuristics.

Architectural Boundary: etalon-wgsl-forge Compiles & Certifies; the Engine Executes

Whether you are browsing high-level system design or auditing GPU execution safety, the core architectural separation is strict: QualiaDB owns domain semantics, policy admissibility (`ExactnessProfile` / `ADR 0003`), and weight containers (`P64`), while etalon-wgsl-forge owns deterministic shader lowering, Naga AST validation, and hardware-vs-CPU oracle certification:

Forge — Deterministic Producer & Certifier (etalon-wgsl-forge)

Compiles GPU compute kernels from a typed mathematical specification (KernelSpec) and an orthogonal hardware execution schedule (Schedule), validates the generated shader AST via Naga, and certifies every kernel on real GPU silicon against an independent CPU reference oracle. Also transcodes GGUF/Safetensors weights into the 64-byte aligned p64 container.

Runtime Engine — Governed Dispatch (qualia-core-db & etalon)

The in-process runtime loads adapter-keyed certified shaders and p64 weight volumes (`{stem}.execution-profile.json`) to execute inference, graph sieves, and continuum physics. Sustained decode throughput is measured by the runtime engine (e.g., ~18.8 tok/s native Vulkan on RTX A2000 for SmolLM2-360M Q8; ~5.9 tok/s in-browser WebGPU).

Typed KernelSpec + Schedule IR Across 5 Target Backends

In etalon-wgsl-forge, a compute kernel is declared once as a pure mathematical DAG (KernelSpec). Tiling, workgroup dimensions, shared-memory staging, and vectorization width live in a separate Schedule descriptor so hardware tuning can never silently alter mathematical semantics. Three-Pillar GPU Oracle Certification (ETA-14, ETA-15, ETA-17)

Every generated kernel is dispatched on the target hardware adapter, read back with deterministic fencing, and compared element-by-element against an independent CPU reference oracle before its adapter-keyed receipt is sealed into QualiaDB:

ETA-14 · TENSOR & DECODE ORACLE

Full GQA Transformer Layer

A complete multi-head GQA transformer decode layer composed of etalon-wgsl-forge kernels is certified on real SmolLM2-360M weights (n_embd = 960, 15 Q-heads / 5 KV-heads, head_dim = 64, ffn = 2560, RoPE base 100k), matching the composed CPU reference oracle to a maximum relative error of 3.28×10⁻⁶ on RTX A2000 Vulkan.

ETA-15 · FDTD & CONTINUUM ORACLE

Maxwell CFL & Poynting Balance

3D FDTD electromagnetic and 2D SWE hydrodynamic kernels in etalon-sim enforce the Courant–Friedrichs–Lewy condition ($c\Delta t\sqrt{\Delta x^{-2}+\Delta y^{-2}+\Delta z^{-2}} \le 1$) prior to dispatch and verify discrete Poynting energy conservation against the 64-bit CPU reference integrator.

ETA-17 · NQUIN GRAPH ORACLE

Bitwise Sieve & Radix Parity

etalon-nquin certifies 48-byte NQuinWire GPU predicate sieves and 8-pass LSD radix sorts against the CPU reference implementation with ExactnessProfile::Exact (oracle_mismatches == 0) and 5-field XOR parity verification.

Hardware Backend Selection & Steward Policy

The Etalon silicon steward selects its GPU backend by capability intersection (f16, subgroup operations, timestamp queries) and records the active adapter in the execution profile; you can also pin a backend explicitly:

# Default is Vulkan (vendor-neutral across AMD / Intel / NVIDIA / ARM / Linux & Windows).
# Pin a backend explicitly:
QUALIA_WGPU_BACKEND=vulkan   # default, full compute & graphics certification
QUALIA_WGPU_BACKEND=dx12     # Windows DirectX 12 hardware lane
QUALIA_WGPU_BACKEND=metal    # Apple Silicon / macOS Metal lane

Execution Profiles & Policy Admissibility (ADR 0003)

  • ExactnessProfile::Exact: Bitwise-deterministic integer, rational, symbolic, or 48-byte NQuin sieve/sort evaluation (oracle_mismatches == 0). Admissible for deontic, identity, and policy gates.
  • ExactnessProfile::DeterministicApproximate { abs_bound, rel_bound }: Certified floating-point kernels with explicit finite error bounds verified against the CPU reference oracle.
  • ExactnessProfile::InteractiveApproximate: Fast-math preview or stochastic rendering lanes — strictly rejected by admit_for_policy_decision() so visual approximations can never influence governance or rights decisions.
  • P64 Weight & Profile Pairing: Converted models pair 64-byte aligned .p64 weight volumes (Q4_K_M / F16 / Q8_0 with per-tensor CRC-32C) with a sibling {stem}.execution-profile.json receipt.
