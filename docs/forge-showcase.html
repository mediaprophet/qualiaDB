WGSL Forge

A deterministic GPU-kernel generator, validator, and oracle-backed correctness certifier. It does not use an LLM, and it does not run inference.

The Forge produces; the Engine runs

This boundary is the whole design — read it once and the rest follows:

Forge — producer & certifier

Generates GPU kernels from a typed DAG-IR, validates them, and certifies every one against a CPU oracle. Also transcodes GGUF → the native p64 weight container. It is build-time tooling.

Engine — runtime

The in-process inference engine runs the p64 model. Throughput (tok/s) belongs to the engine, not the forge — measured at ~18.8 tok/s decode (SmolLM2-360M Q8, RTX A2000, Vulkan, compute-bound).

One IR, many backends

A kernel is described once as a compute graph; the forge lowers it to each target and the schedule is kept separate from the math, so optimisation can never silently rewrite what is being tested.

Generated + certified kernels include the math substrate the rest of the engine builds on:

  • Dense linear algebra — GEMM, GEMV, and a double-single (df64) emulated-f64 GEMM for f64-on-any-GPU.
  • Transforms / DSP — radix-2 FFT feeding the audio path (STFT, CQT, HRTF).
  • Reductions & selection — affine, top-k (shared-memory + barriers).
  • LLM decode kit — RMSNorm, real RoPE (interleaved + NeoX), multi-head GQA attention, SwiGLU, on-device Slice, and a transposed-B GEMM that consumes native [out,in] weights.

Honest scope: the legacy kernel kit (GEMM/GEMV/FFT/affine/top-k) lowers to all targets above; the LLM decode graph is currently certified through the executor and not yet emitted as standalone source on every backend.

Certified, not asserted

Every generated kernel is run on the real GPU and diffed against an independent CPU oracle. The headline proof for this release:

A full multi-head GQA transformer decode layer — composed of forge ops — was certified on the real weights of SmolLM2-360M (n_embd 960, 15 heads / 5 KV-heads, head_dim 64, ffn 2560, RoPE base 100k), matching the composed CPU oracle to a maximum relative error of 3.28×10⁻⁶ on an RTX A2000. That proves the kernels are correct — it is certification, not a tok/s claim.

Pick your pipeline

The engine selects its GPU backend by capability and reports it; you can pin it for the vendor-neutral path:

# Default is Vulkan (vendor-neutral: AMD / Intel / NVIDIA / ARM / Linux).
# Pin a backend explicitly:
QUALIA_WGPU_BACKEND=vulkan   # default, recommended
QUALIA_WGPU_BACKEND=metal    # Apple
QUALIA_WGPU_BACKEND=dx12     # Windows-native (see caveat)
Vulkan
Default & verified working path. The portable, vendor-neutral choice.
Metal / GL
Selectable; Metal is the Apple-native path.
DX12
Device initialises, but decode is not yet validated (currently hangs) — use Vulkan.

What we are not claiming

  • The forge does not run inference and is not "faster than the engine" — those are different jobs; tok/s is the engine's.
  • The LLM decode graph runs through the certification executor; it is not yet emitted as portable shader source on every backend.
  • Sub-2-bit / ternary (1.58-bit) FFN is not a shippable path. Post-training-quantising a model that was not trained ternary destroys it (perplexity collapses); activation-aware scaling helps but does not rescue it. The shippable compression is standard Q4_K_M, transcoded to p64 verbatim.
  • Tensor cores (CUDA WMMA / wgpu coopmat) are built and certified as kernels but are not yet on the live decode path; coopmat depends on an unreleased wgpu fix.
