Native Inference Architecture

QualiaDB runs LLM inference entirely in-process. No Ollama, no Python runtime, no external HTTP server:

GGUF Model Loading

Memory-mapped GGUF files via `memmap2` - zero heap allocation

GPU Dispatch

DirectML (Windows), Accelerate (macOS), wgpu/Vulkan (Linux)

Phase 8 Bifurcation

SPSC ring buffers for real-time governance interception

128 MB RAM Cap

Strict memory limit for edge device compatibility

Privacy & Security

All inference happens locally on your device. No data ever leaves your machine. The Webizen Sentinel validates every token in real-time to prevent hallucinations and enforce fiduciary boundaries.

Phase 8 Bifurcated Compute

QualiaDB's unique governance architecture uses two wait-free SPSC ring buffers:

LLM Engine thread  ──LogitSummary──►  LogitStream (cap 1024)  ──►  Webizen Sentinel
                   ◄──DenyRollback──  ControlStream (cap 16)  ◄──  (calling thread)

How It Works

  1. LLM thread embeds current token and calls GPU dispatch
  2. Argmax + anomaly flag packed into fixed-size LogitSummary (no heap)
  3. Sentinel reads summary in real-time
  4. If anomaly detected (e.g., 0x99 byte for anachronism), injects DenyRollback
  5. LLM thread substitutes safe neighbour token and continues
  6. Loop ends at EOS token or MAX_OUTPUT_TOKENS (2048)

Mid-Generation Correction

Unlike post-hoc filtering, QualiaDB can correct the LLM mid-generation. If the Sentinel detects a violation of the Rights Ontology or a factual error, it immediately triggers a rollback before the token is committed to the output stream.

Using the LLM API

Rust API

use qualia_core_db::llm_agent::LocalLlmAgent;

async fn run_inference() -> Result {
    let agent = LocalLlmAgent::new("gemma-3-1b-it-q4_0.gguf")?;
    
    let prompt = "Explain the architecture of QualiaDB.";
    let graph_context = "{}"; // JSON serialized semantic graph
    
    let output = agent.infer(prompt, graph_context).await?;
    
    Ok(output)
}

CLI

# Run inference with the CLI
qualia llm infer --model gemma-3-1b-it-q4_0 "Explain quantum computing"

Daemon API

curl -X POST http://localhost:4242/llm/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemma-3-1b-it-q4_0",
    "prompt": "Explain the architecture of QualiaDB",
    "max_tokens": 512
  }'

Integration with Semantic Graph

The LLM is deeply integrated with QualiaDB's semantic graph:

Graph-Aware Inference

# The LLM can query the graph during generation
prompt = """
Based on the following information from my knowledge graph:
- I have 3 children: Alice (age 10), Bob (age 8), Carol (age 5)
- Alice is allergic to peanuts
- Bob has asthma

What should I pack for a family camping trip?
"""

SPARQL Generation

# LLM can generate SPARQL queries
prompt = "Find all people over 30 who live in New York"
# LLM generates:
# SELECT ?person ?name WHERE {
#   ?person a ex:Person ; ex:name ?name ; ex:age ?age ; ex:city "New York" .
#   FILTER (?age > 30)
# }

Structured Output (JSON-LD)

# LLM can output structured JSON-LD
prompt = "Extract information about Alice and return as JSON-LD"
# LLM generates:
# {
#   "@context": "http://example.org/",
#   "@graph": [{
#     "@id": "ex:alice",
#     "@type": "Person",
#     "name": "Alice Smith",
#     "age": 30
#   }]
# }
